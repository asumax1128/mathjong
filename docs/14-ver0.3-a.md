# MATHJONG Ver.0.3-A 実装記録 — 9枚制・数学Ⅰ／Ⅱモード・刻子・ポン・新役

作成: 2026-10-25 ／ 基準: Ver.0.2.1（main `c41b549dff373b05f3241e9b8abc0aac97c0f0cc`）／ ブランチ `feature/v0.3-a-rules-pon`
画面 `0.3.0-a`・エンジン `0.3.0-a`（版番号は暫定。オーナー承認で確定）。点数はすべて試作段階の暫定値。

研究資料（Draft PR #6、`research/v0.3-simulation-data`）は参照のみ。その数値は簡易モデルによるもので、本エンジンの保証値ではない。

## 1. ルール（9枚制）
- 配牌8枚、ツモ後9枚。3面子で和了（雀頭なし）。11枚制・雀頭は実装しない。
- 面子は2種類（`rules.melds[i].kind`）：
  - `formula`＝数式面子（関数牌＋角度牌＋結果牌の正しい等式）。index は従来と同じ（0〜）。
  - `koutsu`＝刻子（同じ種類の牌3枚）。数式面子の後ろに追加。`type` に牌の種類を持ち、`fn`/`deg`/`value` は持たない（数式系の役で誤用しない）。
- 数式面子と刻子は自由に混ぜられる。門前なら役なしでも和了（通常和了1点）。チー・ポンを1回でもした手は役が必要。
- 既存の数式系の役（`formulaOnly: true`）は **3組とも数式面子のときだけ** 評価する。混合形には付かない（＝鳴いた混合形は和了不可）。新しい混合役は追加しない。
- チーとポンは合計2回まで（`rules.maxCalls`）。九角無双は従来の9枚形（門前限定）。

## 2. 数学Ⅰ／数学Ⅱ（`src/engine/config.js` の `modeConfig(mode)`）
| | 数学Ⅰ `math1` | 数学Ⅱ `math2`（暫定既定） |
|---|---|---|
| 角度 | 0°〜180° の9種（度数法） | 0〜2π の17種（弧度法） |
| 関数牌 | 各12枚 | 各16枚 |
| 角度牌・結果牌 | 各4枚（結果13種） | 各4枚（結果13種） |
| 合計 | 124枚 | 168枚 |
| 数式面子 | 26種（tan90° なし） | 49種（従来どおり。tan(π/2)・tan(3π/2) なし） |
| 刻子 | 25種 | 33種 |
- 内部の角度は常に度（`deg`）。弧度法は表示だけ（`angleUnit`、角度の種類に `unit`・`rad` を持たせて描画で切り替え）。π の分数は縦組み（分子・分母）で表示。0 と 2π は別の牌。
- 数学Ⅰでは第3・第4象限を使う役（三象限巡り・第3象限一色・第4象限一色）が成立しないため無効（全組合せで成立しないことを単体テストで確認）。ガイド・ヒントに出ない。
- モードは設定画面で選び、「新しい対局」で反映。進行中の局・次の局では変わらない。保存キー `mj-mode`、URL `?mode=math1|math2`。
- `makeConfig({ legacy: true })`／`LEGACY_V02_CONFIG`＝Ver.0.2.1 までの規則（刻子・ポンなし）。互換テストと `tools/simulate.mjs --legacy` 用。画面では `?rules=legacy`（ローカル開発環境のみ）。

## 3. ポンと宣言の優先順位（`src/engine/game.js`）
- 他家3人の打牌で、手牌に同じ種類が2枚あればポン（`ponOption`）。公開刻子を作り、1枚捨てる。鳴いた人の打牌番になり、間の席は飛ばす。
- 優先順位：**ロン ＞ ポン ＞ チー**。打牌者から手番順に近い席から1人ずつ判断する。
  - ロン：その場で和了（より近い席は既にロンを見送っている＝アタマハネ）。
  - ポン・チー：選択を保留し、後続の席のロン判断が終わってから確定する（**ほかの人にロンの機会がある間は確定しない**）。
  - 複数ポン：最初に選ばれたポン（＝最も近い席）だけが有効。近い席がポンを選んだら、後続の席にはポン・チーを聞かない（ロンだけを聞く）。
  - ポンがあればチーより優先。誰も選ばなければ次の人のツモ。
- 牌は id で移動し、鳴いた牌は河から公開面子へ1回だけ移る（不変条件 `checkInvariants` を毎手確認）。
- `pending()` は宣言待ちに `pon`（`{meld, use}` または `null`）を含む。公開面子は `{ meld, kind, call: 'chi'|'pon', tiles, claimed, from }`。

## 4. 新役（`category: 'koutsu'`）
| 役 | 条件 | 鳴き | 仮得点 |
|---|---|---|---|
| 対々和 | 3組すべて刻子 | 可 | 3 |
| 三暗刻 | 3組すべて門前の刻子 | 門前限定 | 5 |
| 正弦一色／余弦一色／正接一色 | 9枚すべて sin／cos／tan | 可 | 役満16 |
- 三暗刻：ロンで最後の刻子を完成させた場合も成立（**暫定。通常の麻雀とは異なる**）。`rules.sanankouRonCounts: false` で除外できる。ガイドに明記。
- 門前の刻子3組は対々和＋三暗刻（1+3+5=9点）。一色と対々和が同時なら役満の処理を優先（役満の点だけ）。

## 5. AI（`src/engine/ai.js`）
- 判断材料は公開情報だけ（自分の手牌・公開面子・全員の河）。他家の手牌・山の順番は使わない。
- 数式面子の戦略を保つため、門前の手では「手の内で作る刻子1組」ごとに重みへ `koutsuBias`（0.5〜0.55）を掛ける。
- 関数一色は通常 AI に無理に追わせないため、重みの計算では対々和と同じ点数として扱う。
- ポン（`chooseCall`）：
  1. 鳴いた後に役の付く完成形（実質的に対々和）まで、見えていない牌だけで `ponMaxMissing`（2）枚以内で届くこと（取得不可能な牌は数えない）。
  2. 鳴いた後の最良の手の価値 × `ponTempo`（ツモを待たずに刻子が完成する分。速攻型2.5・役重視型1.5）が、鳴かない場合 × しきい値を上回ること。
  - 門前重視型はチー・ポンをしない（性格の違いを維持）。
- 旧規則では刻子がないため、AI の判断は Ver.0.1 と完全に同じ（1,000局の出力一致で確認）。
- 参考（短い通し、各200局程度。正式な統計ではない）：数学Ⅰでポン約0.1回/局、数学Ⅱではほぼ0。数学Ⅱは門前の選択肢が増えたためチーも減る。

## 6. 役候補ヒント（`src/engine/yakuhint.js`）
- 刻子・新役に対応。いまポンできる打牌は、ポンした後の局面（鳴いた手）として評価する（`claimForSeat` に `ponMeld`）。
- 並び順：数式系を優先。刻子系は「あと何枚」に `hint.koutsuPenalty`（1）を足した順位で並べる（同程度なら数式系が先、明らかに近い刻子系は隠さない）。完成（あと0枚）は最優先。**表示する「あと何枚」は常に正確な値**（総当たりの別実装と一致することを単体テストで確認）。
- 鳴いた手に門前限定役は出さない。数学Ⅰに無い角度を使う役は出さない。
- 計算時間：数学Ⅱ（刻子込み 95,284 通り）で初回約120 ms、以降約10 ms（Node.js）。従来どおり warmUp で事前計算。

## 7. チーのオートパス（`src/ui/autopass.js`）
- ON で自動パスするのは「チーだけができる」宣言だけ。ロン・ポン・ツモは自動で見送らない。
- ON でロンまたはポンも可能なときはチーを表示しない（「ロンしない／見送る」でチーも見送る旨を注記）。ポンは表示する。
- 宣言ごとに表示方針を固定する Ver.0.2-B の仕様は維持。役候補ヒントは表示中の選択肢と同じ経路。

## 8. 画面（スマホ縦画面基準）
- 設定：モード（数学Ⅰ／数学Ⅱ、新しい対局から）。ヘッダーに「数Ⅰ／数Ⅱ」。
- ポンのボタン（刻子を「1/2 ×3 刻子」と表示）、公開刻子、和了結果の刻子・混合形の注記、チー／ポンの別。
- ガイド：新役（刻子の数式例）、ルール（9枚制・ポン・優先順位・三暗刻の暫定規則）、牌一覧・値表は弧度法／度数法。
- 400px 以下ではロゴを隠し、600px 以下では版番号を隠してヘッダーを1行に収める（320px でも横スクロールなし）。
- タブレット・PC の麻雀卓型 UI は Ver.0.3-C（別 PR）。
