# 数雀（MATHJONG）Ver.0.5-C（仮）実装記録 — タイトル画像の採用＋ツモ演出の強化

作成: 2026-10-27 ／ 基準: main `c8fa8cc`（Ver.0.5-B のマージ）／ ブランチ `feature/v0.5-c-title-tsumo`
版（暫定）：画面 `0.5.0-c`。エンジン `0.5.0-a` は据え置き（ルール・判定・得点・AI・進行は変更なし）。
「Ver.0.5-C」は実装側の仮の名前で、正式な版名はオーナーが決める。

## 1. 方針
- 視覚の変更だけ。`src/engine` と `tools` は変更していない。ゲームのルール・判定・得点・AI・進行は変更していない。
- 軽さ：演出は CSS のアニメーションが中心（`transform`・`opacity`）。タイトル画像は画面の大きさと解像度に合わせて、3つの大きさから選ぶ。

## 2. タイトル画像の採用
- 画像：オーナーが正式採用した「数雀」のロゴ（背景透過の PNG）。
  - **正式採用ファイル：1536×1024px、3:2、8bit RGBA、2,686,387 バイト、SHA-256 `aee4ed6781d44eef9f1a666a56ac04e27c16790a376cf770a112f48434a7ca1f`**。
  - 色・構図・文字は改変していない。
  - 初版（`60a0698`）の画像（1448×1086、4:3、SHA-256 `afb55d8e…e4b7b`）は、正式採用元とは別の画像だったので、**置き換えた**。旧画像のファイル（`title-logo-1448.png`・`-1084.png`・`-724.png`）は削除し、参照も残していない。
- 元画像の照合：オーナーから受け取った zip（PNG 1枚）を、専用の空フォルダに展開して SHA-256 を計算し、正式採用のハッシュと**完全に一致**することを確認した。
  - 元画像は**バイト単位で同一**のまま `src/ui/title-logo-1536.png` に置いた（`cmp` で確認。単体テストと E2E でも毎回確認する）。
- 縮小版（読み込みを軽くするため）は、元画像から作った。
  - 幅：384・576・768・960・1152（高さは 256・384・512・640・768）。**すべて 3:2**（幅 ×2 ＝ 高さ ×3 が整数）。
  - 縮小だけで、比率・色・構図は変えていない。アルファ乗算済みで縮小するので、透過の縁に輪郭が出ない。PNG は可逆圧縮（画素の損失なし）。
  - ファイルの大きさ：384 幅 0.19MB、576 幅 0.39MB、768 幅 0.65MB、960 幅 0.98MB、1152 幅 1.37MB、1536 幅（元画像）2.69MB。
- 品質の確認（縮小版5つ）：
  - 四隅は完全な透明（アルファ 0）で、全体の平均色・平均アルファは元画像との差が 0.4% 以下。
  - 別の方法（面積平均）で作った参照画像との誤差は、アルファで平均 0.4〜0.7/255、不透明な画素の色で平均 2.3〜3.6/255（縮小方法の違いの範囲）。
  - アルファの最大値は、元画像が 254、縮小版が 255（縮小時の丸めによる 1/255 の差。255 の画素は全体の 0.2〜2.2%）。見た目に影響しない範囲。
- 配置：置き場所は `src/ui/`。開発用サーバー（`tools/serve.mjs`）の配信の許可（`src/ui/` 内の小文字・数字・ハイフンの名前の PNG）の範囲内なので、許可の設定は変えていない。
- 表示（`titleHTML`）：
  - 旧来の文字のロゴ（「数雀」「MATHJONG」）を、`<img>` に置き換えた。`alt` は「数雀（MATHJONG）」。`width`・`height` は元画像の大きさ（1536×1024）。
  - **枠は常に 3:2**。幅は「画面の幅−左右の余白 32px・380px・画面の高さの 45%」の最小値（低い横画面、高さ 500px 以下は 66%）。高さは `auto`。画像は歪まず、余白も出ない。
  - 390×844 では、スタートボタンが最初の画面に収まる（811px）。375×667 以下の小さい画面では、従来どおり下へスクロールする。
  - 画像が読み込めない場合は、`alt` の文字が表示される。
- ゲーム画面のヘッダーの小さな文字のロゴ（「数雀 Ver.…」）は、そのまま。

### 2.1 画像の読み込みの最適化（監査 P3-B）
- **指摘**：低い横画面で、必要以上に大きな PNG を取得していた（初版）。
  - 原因：`srcset` の `sizes` が、実際の表示幅（高さで決まる）とずれていた。
  - 再現（初版 `60a0698`、Chromium）：667×375・DPR3 で、必要な幅 653px に対して 1448 幅（2.9MB）を取得（必要の 2.22 倍）。844×390・DPR3 でも 2.13 倍、932×430・DPR3 で 1.94 倍だった。
- **修正**：
  - `sizes` を、実際の CSS の表示幅と同じ式にした。通常は `min(100vw−32px, 380px, 45vh)`、低い横画面は `min(100vw−32px, 380px, 66vh)`。
  - 幅の刻みを 6段（384・576・768・960・1152・1536）にして、DPR 1〜3 と低い横画面に細かく対応した。
  - `styles.css` の幅の式と `sizes` を同じにし、単体テストで一致を確認する。
- **結果**（18の画面×解像度。必要な幅＝実際の表示幅×DPR）：
  - すべてで、必要な幅以上で最小の画像を**1枚だけ**取得する。
  - 必要な幅に対する比は、667×375・DPR3 で 1.03 倍（768 幅）、844×390・DPR3 で 1.24 倍（960 幅）、932×430・DPR3 で 1.13 倍（960 幅）、320×568・DPR2 で 1.13 倍（576 幅）。
  - 取得は、実際にネットワークで取得されたファイルの幅と枚数で確認する（E2E）。

## 3. ツモ演出の強化
- 演出の仕様（Ver.0.5-B の仕組みに「ツモ」を追加）：

  | | ロン | ツモ（新規・強化） |
  |---|---|---|
  | 文字 | 「ロン！」 | 「ツモ！」 |
  | 長さ | 0.80秒 | **1.00秒**（目安 0.9〜1.1 秒） |
  | 色 | 赤〜金 | **青白〜金** |
  | 動き | 文字が大きく現れて収まる。赤〜金のフラッシュ。盤面が揺れる。 | 文字が小さな状態から大きく現れて収まる（ぼかしが晴れる）。青白〜金の閃光。**広がる光の輪**。盤面が軽く揺れる。 |
  | 牌 | 和了牌（打牌）を大きく表示 | 和了牌（**自力で引いた牌**）を大きく表示 |
  | 名前 | 和了した人 | 和了した人 |

- 見分け方：色の系統（赤金／青白金）と、光の輪（ツモだけ）。「自力で引き当てた達成感・神秘感」として、光の輪が内側から広がる。
- 優先度：ロンと同格（ロンとツモは同じ局に同時には起きない）。どちらもポン・チーより高く、表示中のツモをポン・チーで消さない。
- 簡易表示（設定）と reduced motion：文字だけ（閃光・光の輪・和了牌・揺れなし）。P2-1 の修正（演出の開始時にモードを固定）は、ツモにもそのまま適用される。
- 結果画面・精算・次の局への進行は変えていない。結果画面は演出を待たずに開く（演出は、結果画面の上に重ねて表示する）。
- 出る場面：自分・AI のツモ和了。
- 画面揺れの横はみ出し（修正）：揺れで盤面を ±5px 動かすと、一瞬ページが横にはみ出して、横スクロールができてしまっていた（ロンの揺れにも同じ現象があった）。`#app { overflow-x: clip; }` で切る。`clip` はスクロールの枠を作らないので、画面下の操作バー（sticky）や重ねて表示する画面（fixed）には影響しない。

## 4.1 Codex 監査指摘への対応（最終修正）
- **P3-A（タイトル画像が正式採用元と異なる）**：正式採用の画像（1536×1024、SHA-256 `aee4ed67…7ca1f`）に置き換えた（§2）。
- **P3-B（低い横画面での PNG の過大取得）**：`sizes` を実際の CSS の表示幅に合わせ、6段の縮小版で解像度に細かく対応した（§2.1）。
- **P3-C（和了牌のテスト）**：表示される和了牌を、実際にツモした牌と直接比べる検査にした（§4）。意図的に別の牌（手牌の先頭）を表示するよう壊した版では、この検査が失敗することを確認した。
- 変更していないもの：`src/engine`・`tools`、ツモ・ロン・ポン・チーの演出の仕様、リーチ・オートパス、AI、ゲームのルール・得点。
