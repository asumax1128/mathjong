# 数雀｜オンライン対戦 段階2「2人で1局通し」実装メモ

- 設計の正本は [docs/79](79-online-play-design.md)、段階1の実装メモは [docs/80](80-online-stage1-lobby.md)。
- 未決事項 U1〜U11 は、設計書の推奨どおりに決定済みとして実装した。
- **エンジン（`src/engine`）は変更していない。**

段階1の制約は、この段階でもそのまま守っている。

- 接続先はエミュレータだけ。
- 入口は「ローカル開発環境＋`?online=emu`」のときだけ出す。
- `ONLINE_PUBLIC = false`。

## 1. 構成

| ファイル | 役割 |
|---|---|
| `src/ui/online-protocol.js` | 配信の形と、ゲスト側の表示用モデル。詳細は下記。 |
| `src/ui/online-host.js` | ホストの進行役（HostRunner）。詳細は下記。 |
| `src/ui/online-session.js` | 進行役・ゲストと Transport のつなぎ。詳細は下記。 |
| `src/ui/online-lobby.js` | 段階1のロビーに次を追加：空席の CPU の選択（`setCpu`・`meta.cpus`）、開始時の席決め（`planSeats`）、`startMatch` での席の書き直し。 |
| `src/ui/online-ui.js` | ロビーに CPU の選択欄を追加。開始すると、ホストは進行役を動かし、ゲストは配信を受ける。対局の画面は app.js の卓。 |
| `src/ui/app.js` | オンラインの対局の窓口（`onlineGame`）を追加。詳細は下記。 |
| `firebase/mathjong-rules.cjs` | 次を追加：`seats/$seat` の `kind:'cpu'`（uid を持たず `cpuId` を持つ）と `cpuId`、`meta.cpus`。 |

`online-protocol.js` の中身：

- `pub`（公開）と `priv/$seat`（本人だけ）の射影。
- 席の回転。
- `RemoteTable`：`Game.prototype` を使った、自分が席0の表示用モデル。

`online-host.js`（HostRunner）の中身：

- ホストだけが Game と試合管理（match.js）を動かす。
- CPU の席は既存の AI（`decideCharacter`）。
- 人間の行動は `act` で受け、検証してから適用する。
- 制限時間を扱う。
- 局の結果と次局への進行、試合の進行（4局戦・8局戦・`MAX_ROUND`）を扱う。

`online-session.js` の中身：

- ホストは `pub/state` と各人間席の `priv/$seat` を、1回のまとめ書き（update）で書く。
- ホストはゲストの `act/$seat` を購読する。
- ゲストは `pub/state` と自分の `priv/$seat` を購読し、操作は `act` への追記だけ。

`app.js` に追加した窓口（`onlineGame`）の動き：

- 配信値から RemoteTable を作り、`S.game` の代わりに渡す。
- これにより、既存の卓・ヒント・聴牌サポート・自動パス・オートツモ切りをそのまま使う。
- 操作はエンジンに適用せず、送るだけにする。

## 2. 決定事項の実装

- **空席の CPU（U7）**
  - ホストが、ロビーの空席ごとに12人から選ぶ。既定は自動。
  - 自動の席は、開始時に選ばれていない人から無作為に選ぶ（ローカルの「おまかせ」と同じ `drawOpponents`）。
  - ブリーフにある `selectOpponentIds` は、このリポジトリに存在しない。そのため、既存の `drawOpponents` を使った。
- **席と最初の親（U9）**
  - 開始時に、ホストの端末で無作為に決める（`planSeats`）。
  - 決めた並びで `seats/0..3` を書き直す（CPU の席は uid なし）。
  - あわせて、`host` に `seedBase` と最初の親を、`meta.status` に `playing` を書く。これらを1回のまとめ書きで行う。
  - 書き直すことで、「席の番号＝ゲームの席」になる。その結果、`priv/$seat`・`act/$seat` のルール（席の uid で判定）がそのまま使える。
- **宣言ウィンドウ（docs/79「4.1」）**
  - 打牌のたびに、宣言できる人間全員へ、その時点の選択肢を同時に出す（15秒）。
  - 全員の応答が揃うか締切で締め、エンジンの順番で `respond()` に流す。
    - 順番：近い席から。ロン＞ポン＞チー、アタマハネ、後続ロンによるチーの取消し。
  - CPU は、自分の番が来た時点で判断する。
  - 集めたポン・チーがその時点で成立しないときは、見送りに直す。その席には「他家の宣言が優先されました」と知らせる。
- **再質問ウィンドウ**
  - 対象：ポンを選んだが、より近い席のポンで無効になり、ロンが残っている席。
  - その席にだけ、短い再質問（ロンする／見送る・15秒・時間切れは見送り）を開く。
  - 詳細は「4」。
- **制限時間**
  - 手番：45秒。時間切れはツモ切り（鳴いた直後でツモ牌がないときは手牌の最後の牌）。
  - 宣言：15秒。時間切れは見送り。
  - 結果：20秒で次局へ。全員の「次へ」がそろうか、ホストが押すと早まる。
  - 締切はホストの時計で判定し、全員に同じ値を配信する。
  - 画面上部の帯に、残り秒数と「誰の番か」（宣言の窓では、誰に選択肢があるかは出さない）を表示する。
  - 時間切れの連続回数は、席ごとに数える（`pub.timeouts`）。人間が操作すると0に戻る。離席・代打ちへの接続は段階3。
- **結果の同期**
  - 精算はホストだけが行い、`pub.match`（試合の状態）・`prevScores`・`lastRound` を配信する。
  - ゲストは自分を席0に回して、既存の結果・最終結果の画面に出す。
- **自動パス・オートツモ切り・ヒント・聴牌サポート**
  - 各端末の設定のまま、端末側で行動を送る（ホストには預けない）。
- **牌譜**：オンライン対戦は記録しない（設定と最終結果に、その旨を表示）。
- **CPU の手番の間**：ホストで 600ms。ローカル試験用の `?onlineCpuDelay=` で変えられる。

## 3. 設計書からの変更点

1. **`pub`・`priv` は JSON 文字列で包む（`{ seq, s }`）。** RTDB は空の配列・null を保存せず、配列の形も崩れるため。
2. **局の終わりには、全員の手牌を `pub.game.revealed` で公開する。** 既存の結果画面の「全員の手牌を見る」のため。局の途中は枚数だけを配信する。
3. **ホスト自身の席は通信を通さない。** 配信値を手元の画面へ直接渡し、操作も直接進行役へ渡す。ホストの席の `priv` は DB に書かない。
4. **「次へ」の扱い。**
   - 全員の「次へ」、20秒、ホストの「次へ」のいずれかで、次局へ進む。
   - ホストが押すと、全員が待たずに次局へ進む（ブリーフの「20秒またはホストの操作」）。
5. **BroadcastChannel の簡易経路（docs/79「9.0④」）は実装していない。** ブリーフで任意（「使ってよい」）のため。CI と試験は、メモリ上の偽バスと RTDB エミュレータの2経路で行う。

## 4. 再質問ウィンドウについて（重要）

- **現行のルールセット 2 では、この局面は物理的に起きない。**
  - 「より近い席のポンで、後ろの席のポンが無効になる」には、同じ牌を2人がポンできる必要があり、1種類の牌が5枚以上要る。
  - 5枚以上あるのは関数牌（12枚・16枚）だけで、ルールセット 2 は関数牌のポンを禁止している。ほかの牌は4枚。
  - 確認：数学Ⅰ200局・数学Ⅱ100局の自動対局で、発生は0回。
- **それでも実装し、試験した。**
  - 関数牌のポンができるルールセット 1 で局面を組み立て、次を確かめた（`tests/online-host.test.js`）。
    - 再質問は、その席にだけ、15秒で開く。
    - 選択肢はロン・見送りだけ。
    - ロンすれば和了。結果はローカルの1席ずつの判断と一致する。
    - 時間切れは見送りで、近い席のポンが成立する。
  - 進行役の処理は、ルールセットによらない。

`tests/online-host.test.js` の項目：

- 並列収集とエンジン順の適用は、ローカルの1席ずつの判断と、記録・結果が完全に一致する。
  - 方針つきの4人。数学Ⅰ33局・数学Ⅱ2局。
  - アタマハネ・後続ロンによるチーの取消し・ポン＞チー・ロン＞ポンが、実際に起きることも確かめる。
- 再質問（ロン・時間切れ）。
- 制限時間（45秒のツモ切り・15秒の見送り・20秒の次局・連続回数）。
- 行動の検証（古い sid・他人の席・不正な牌）。
- 配信の射影。
- RemoteTable の回転と既存計算。
- **偽バス上での通し**：ホスト1＋ゲスト3で1局戦・4局戦・8局戦（数学Ⅱ）、人間2＋CPU2で4局戦。いずれも次を確かめる。
  - 全端末の持ち点・順位が一致する。
  - 受信データに他家の手牌がない。
  - CPU の席の priv がない。

`tests/online-rules-emulator.mjs` の段階2の項目：

- CPU の席はホストだけが書け、uid を付けられない。
- CPU の選択はホストだけが書ける。
- ゲストは開始（席の決め直し）をできない。
- CPU の席の priv は誰も読めず、act には誰も書けない。
- 席が変わった後は、ゲストは新しい自分の席の priv・act だけを使える。

`tests/e2e/online-match.mjs` の項目：

- 2コンテキスト（ホスト・ゲスト）＋CPU 2人で、1局戦を画面のタップだけで最後まで打つ。
- 両端末の持ち点・順位が一致する。
- ゲストの REST で、他家・CPU の priv と `host` が読めない。
- 受信データと画面のモデルに、他家の手牌の中身がない。
- 残り時間の帯が出る。
- ホストが部屋を出ると、ゲストに「閉じられました」と出る。

CI：`.github/workflows/online-lobby.yml`。エミュレータのジョブに、`tests/e2e/online-match.mjs` を追加した。
