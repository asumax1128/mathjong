# 数雀 Ver.0.7 第1段階｜麻雀卓と下部「ヒント・数式確認」エリア

オーナー決定：2026-10-29（D24、[承認済みロードマップ](45-v07-v11-roadmap.md)）。参考画像は一般的な紺色の麻雀卓、数雀自体の現在画面ではない。**画像の黒い下部スペースを削る提案は撤回し、既存ヒント・数式確認の専用スペースとして使う**。

## この開発ブランチの変更範囲

- UI画面のみ **v0.7.0-a（開発試作版）**。エンジン0.5.0-a、ルール、山、AI、保存キー、初心者の部屋、全12人のキャラクター/選択/詳細は変更しない。
- 数学Ⅰ/Ⅱ・局/山・親の公開情報を麻雀卓中央に集約。上家・対面・下家は従来の `panelHTML` と `riverHTML` を再使用し、見える手牌/河やチー/ポン/親・リーチ・点数は消さない。並びはスマホ2列ベース＋中央局パネル、PC横では左右の対戦相手と中央卓。
- 自分の河、公開面子、手牌を卓の下側に配置。既存の9枚手牌表示、物理牌ID、選択/ツモ牌の区別、長押し並べ替え、ヒントの色枠、2回タップ打牌を変更しない。
- 手の下に `study-dock` を新設し、**既存の2段階ヒント出力 `S.hintText` を `.self` から移動**。ヒントOFFなら見出しと短い案内、ONなら1段階「発見ヒント」、`fh-confirm` で2段階「数式確認」。`S.hintOpen` や計算関数、ヒント回数カウント、色枠と一覧切替、合法操作ボタンは変更しない。
- 学習エリアを独立スクロール。ボタンは従来のfooter `.bar` に置く。スマホ縦（320/375/390/430px）、高さ568/667/844/932、スマホ横、iPad/PCの可読性・横スクロールをE2Eで確認。狭い縦サイズでは相手の河を盤面内スクロールさせ、手牌・ヒント・操作を優先する。
- 背景に紺・深緑の卓風CSSを採用。**牌のサイズ・数式表記は変更しない**。参考画像そのもの、麻雀牌の図柄、ロゴ等はコピーしていない。

## 互換性のための注意

- `#app:has(> .bar)` を使い**対局中だけ**固定縦領域に変更し、初心者の部屋・タイトル等を巻き込まない。iOS Safariの対象版と低い画面高ではスクロールとタップ操作を実機で再確認する。
- `.opponents` 内だけスクロールできる状態のため、他家の最新捨て牌や鳴き面子を見つけにくくならないかを実機で確認。必要なら今後のUI第2段階で河の折り返し規則・最新捨て牌の自動スクロール等を安全実装する。
- Ver.0.7完成版を意味しない。局情報・河・ツモ牌・操作ボタン・ヒントの安定を検証してから次の段階へ進む。自動Chromiumの合格を**iPhone Safari実機合格**と呼ばない。

## CIで重点的に確認する項目

- `board-center`（局情報）、`study-dock`（手牌より下・操作バーより上）、ヒントの新表示場所、二段階 `fh-confirm`、従来の色枠・数式・役候補表示。
- バーが端末画面内、手牌の幅30px以上、タップ操作、縦横スクロール、2回タップとドラッグ。
- AI12名の数理・性能回帰、数学Ⅰ/Ⅱ4局/8局、初心者の部屋1〜6、旧結果・再戦・再現URL・保存互換。
- プレビューと手動実機確認が未済なら、本番には出さずPRで検証を継続。
