## この開発ブランチの変更範囲

- UI画面のみ **v0.7.0-a（開発試作版）**。エンジン0.5.0-a、ルール、山、AI、保存キー、初心者の部屋、全12人のキャラクター/選択/詳細は変更しない。
- 数学Ⅰ/Ⅱ・局/山・親の公開情報を麻雀卓中央に集約。上家・対面・下家は従来の `panelHTML` と `riverHTML` を再使用し、見える手牌/河やチー/ポン/親・リーチ・点数は消さない。対面を上、上家・下家を中央局情報の左右に配置し、局情報とプレイヤー表示を重ねない。
- 自分の河、公開面子、手牌を卓の下側に配置。既存の9枚手牌表示、物理牌ID、選択/ツモ牌の区別、長押し並べ替え、ヒントの色枠、2回タップ打牌を変更しない。
- スマホ縦は手の下、タブレット横は右側に `study-dock` を配置し、**既存の2段階ヒント出力 `S.hintText` を `.self` から移動**。ヒントOFFなら見出しと短い案内、ONなら1段階「発見ヒント」、`fh-confirm` で2段階「数式確認」。`S.hintOpen` や計算関数、ヒント回数カウント、色枠と一覧切替、合法操作ボタンは変更しない。
- 学習エリアを独立スクロール。ボタンは従来のfooter `.bar` に置く。スマホ縦（320/375/390/430px）、高さ568/667/844/932、スマホ横、iPad/PCの可読性・横スクロールをE2Eで確認。タブレット横（幅1000px以上・高さ600px以上）は左約62%が卓と手牌、右約38%が学習ドック。1024×768・1180×820・1366×1024を含めて検査し、ヒントOFFでも右領域を維持する。スマホ横には分割を強制しない。短い画面は卓内を縦スクロールでき、操作バーは下端に残す。
- 背景に紺・深緑の卓風CSSを採用。**牌のサイズ・数式表記は変更しない**。参考画像そのもの、麻雀牌の図柄、ロゴ等はコピーしていない。

## 互換性のための注意

- `#app:has(> .bar)` を使い**対局中だけ**固定縦領域に変更し、初心者の部屋・タイトル等を巻き込まない。iOS Safariの対象版と低い画面高ではスクロールとタップ操作を実機で再確認する。
- 卓全体・河・学習内容をスクロールできる。再描画では閲覧位置を維持し、新しい打牌が追加された河は末尾へ移動する（物理牌IDで判別）。自分の手牌変更・段階変更ではヒント内容のスクロールを先頭に戻し、次局では前局の位置を持ち越さない。実機で最新捨て牌の見つけやすさを確認する。
- Ver.0.7完成版を意味しない。局情報・河・ツモ牌・操作ボタン・ヒントの安定を検証してから次の段階へ進む。自動Chromiumの合格を**iPhone Safari実機合格**と呼ばない。

新しい配置検査に旧HEADのCSSだけを一時的に応答させた故障注入は、320pxの中央情報と他家の重なりを検出して失敗した。通常のチェックアウトを旧版に書き換えず、今回の検査が旧不具合を検出することを確認した。

全体E2Eの初回は旧テストが`window.scrollTo`でページ全体を動かした後、画面外の手牌に`elementFromPoint`を呼ぶ箇所で停止。新しい仕様に合わせ`.self .hand`を卓内スクロールで表示し、実際に座標を押せること・実タッチ/マウスの並び替え結果を維持する。例外の握りつぶしや検査のスキップはしない。専用CIにも`--only handReorder`を追加した。

機械可読の検証記録：[validation/v07-table-hint-dock.json](validation/v07-table-hint-dock.json)。CI結果はこのローカル検証後にpushした最新HEADに対して確認する。実装者による確認であり、独立した別担当者の監査ではない。
