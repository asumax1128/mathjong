## 修正1：AUC が定義できないときの例外（`evaluate()`）

### 原因
`aucOf()` は、正例だけ・負例だけのとき `null` を返す。ところが `evaluate()` は、その戻り値に `toFixed` を呼んでいたので、例外（`Cannot read properties of null`）で止まった。行が 0 件のときも、0 で割って NaN を出していた。

### 仕様（修正後）
| 入力 | rows | ronRate | auc | brier | brierBaseline | bins |
|---|---|---|---|---|---|---|
| 0 件 | 0 | null | null | null | null | [] |
| 正例だけ・負例だけ | 件数 | 1 または 0 | **null**（定義できない） | 計算する | 計算する（0） | 計算する |
| 通常（両方を含む） | 件数 | 計算する | 計算する | 計算する | 計算する | 計算する |

### テスト（`tests/sim-v06-tools.test.js`、2件追加）
- **境界**：0 件、正例だけ、負例だけ、1 件で、例外にならず、`auc` が null になることを確認した。
  - Brier を手計算と照合した。
  - 基準率の Brier が 0 であること、確率帯の件数の和と実測を確認した。
- **通常データ**：固定した 300 行で、AUC・Brier・基準率の Brier・確率帯が、修正前（eb9a43b）の `evaluate()` の出力と完全に一致した。
- **修正前のコードでの確認**：境界のテストは失敗した（例外）。通常データのテストは成功した。

## 修正2：ロン後半の演出の E2E の時刻境界（`v05eCutin` の (3)）

### 原因
ロンの演出（2.2 秒）の時間配分（CSS）：
- 中央の表示は 1.10〜1.28 秒で消える。
- 最上部の帯は 1.28〜2.02 秒に不透明で、その後は消えていく。

旧検査は、演出の開始から 1.4 秒たった後に、不透明度を1回だけ見ていた。そのため、検査の実行が遅れて 2.02 秒を過ぎると、帯が消え始めていて失敗しうる（時刻の境界）。

### 修正（検査だけ。演出の時間・CSS・効果音は変更なし）
- 演出の開始から**上限 2.0 秒**（帯が消え始める前）までの間に、次の状態になったことを、繰り返し見て確かめる。
  - 中央の表示の不透明度が 0.05 未満。
  - 最上部の帯の不透明度が 0.95 超、かつ画面上部（上端 0 以上・下端 70px 以下）にある。
- 上限を過ぎても条件を満たさないときは、その時点の表示を出して失敗にする。出す内容：
  - 経過時間
  - 中央・帯の不透明度と位置
  - 演出の種類
  - fx-layer のクラス
- 中央の表示は静止の後に消えること（帯に替わった時刻が 1.0 秒以上）も確かめる。
- 帯に替わった時刻を、合格の行に出す（例「帯に替わった時刻 1290ms／上限 2000ms」）。

### 繰り返しの確認
ロンの検査（`node tests/e2e/play.mjs --only v05eCutin`）を、修正後に 11 回くり返し、すべて成功した。

## 追補（2026-10-28）：最終差分監査（CONDITIONAL PASS）の P3 —— 上限を過ぎた成功の判定
- **指摘**：上の修正2の検査は、表示の条件を満たした観測を、経過時間に関係なく成功にしていた。そのため、上限（2000ms）の後に初めて条件を満たした場合も合格になりえた。
- **修正（検査コードだけ。AI・ルール・演出の CSS・時間・効果音は変更なし）**：
  - 判定を純粋な関数 `judgeRonLate()`（`tests/e2e/ron-late.mjs`）に分けた。
    - `'ok'`：表示の条件を満たし、かつ経過時間 ≤ 上限。
    - `'fail'`：経過時間 > 上限（表示の条件を満たしていても失敗）。経過時間が数でない場合も失敗。
    - `'wait'`：上限以内で、まだ条件を満たさない。
  - 成功には、表示の条件と `elapsed <= LATE_LIMIT_MS` の**両方**が必要。
  - E2E はページの表示（経過時間・中央・帯の不透明度と位置・演出の種類・fx-layer のクラス）を繰り返し観測し、この関数で判定する。
  - 経過時間は、丸めずに上限と比べる。
  - 正常時は、帯に替わった時刻を合格の行に出す（診断の表示を維持）。失敗時は、判定と観測の内容を出す。
- **境界の単体テスト**（`tests/e2e-ron-late.test.js`、5件、`npm test` に含まれる）：
  - 上限直前・ちょうど（1999・1999.9・2000ms）は成功。
  - 上限超過（2000.1・2001・2100・5000ms）は、表示の条件を満たしていても失敗。
  - 条件を満たさない場合：上限以内は待ち、上限超過は失敗。
  - 表示の条件のしきい値の境界、要素がない場合、経過時間が数でない場合。
  - 修正前の判定を再現した関数では、5件中3件が失敗した。
- **E2E の結果**：
  - `--only v05eCutin`：ヘッドレスシェル 3/3、`--channel chromium` 1/1 成功。帯に替わった時刻は 1320.3〜1343.4ms（ヘッドレスシェル）、1309.4ms（chromium）。
  - 上限を一時的に 1200ms にした確認の実行（終了後に元に戻した）では、意図どおり失敗し、判定と観測を出した。
    - `判定 fail、実際の表示：{"elapsed":1200.4,"card":{"t":304,"b":523,"op":0.743717},"banner":{"t":-6,"b":32,"op":0.151945},"kind":"ron","cls":"fx-ron"}`
  - `npm test`：**335/335 合格**（前回 330 件＋境界の単体テスト5件）。
