# MATHJONG — 実機テストと独立監査フロー

作成: 2026-10-24。Ver.0.1以降の開発運用案。ゲームの未承認ルールを勝手に確定させない。

## 1. 担当と権限

| 担当 | 役割 |
| --- | --- |
| ユーザー | iPhone Safari等での実機テスト、ルール・デザイン・公開方針の最終承認 |
| Claude Code | ブラウザで遊べるテスト環境の整備、実装、テスト、問題修正、PR作成 |
| Codex | **独立コード監査**。PR差分・周辺コード・数学的ロジック・境界テストを別視点で検証 |
| ChatGPT | 監査の要約、ユーザーの実機所見と合わせた優先順位付け、Claudeへの修正指示 |

**独立監査は自動起動しない。** 各PRの監査時にユーザーがCodexへ対象PRを渡すか、利用可能なGitHub/Codex連携からCodexレビューを明示的に依頼する。監査の実行が確認できるまでは「監査済み」と呼ばない。

## 2. Ver.0.1 iPhoneテスト開始手順

1. **Claude Code** が最新の `main` と `docs/10-ver0.1-implementation.md` を確認する。
2. `npm test`, `node tools/simulate.mjs --games 1000 --check`, `node tests/e2e/play.mjs` を可能な範囲で再実行。実行していない項目はそう明記する。
3. GitHub Pagesの設定と公開状態を調べる。未設定なら、権限がある範囲で**静的ルート（main / root）**で公開を設定し、HTTPS URLで index とJS/CSSアセットが読み込めることを確認。
4. GitHub側の操作が権限等で不可能な場合は、完了を装わず、ユーザーがGitHub Settings → Pagesから設定できるよう**具体的なUI手順**を報告。
5. iOS Safariの実端末では、下記項目をユーザーが確認する。PlaywrightのiPhone風 viewport は**実機試験の代替ではない**。
6. 公開テストURLと検証commit SHA、`?seed=`を使った再現手順をユーザーに提示する。

**注意**：現在このリポジトリは公開リポジトリ。Pagesを公開すると第三者もアクセス可能。公開に置けない秘密情報・内部資料・本番鍵を含めないこと。公開前にユーザーに公開範囲を説明する。

## 3. 実機テストチェックリスト

### iPhone Safari（最優先）
- [ ] HTTPS公開URLを開く。黒画面／JSエラー／アセット404がない。
- [ ] 縦向きで対局表示、4人の河・公開面子・自分の手牌が読める。
- [ ] 最も長い結果牌（例 `−1/√2`）が欠けずに表示される。
- [ ] 手の選択 → 取り消し → 再選択 → 打牌が誤操作なく動く。
- [ ] 捨てるボタンは何度タップしても**二重処理されない**。
- [ ] チー可能時に正しい選択肢が出る。見送りとチーが正常に動く。
- [ ] ロン/ツモが出たとき、押す・見送るが正常に動く。
- [ ] 九角無双などの特殊和了を再現シードまたはテスト局面で確認（通常ランダム対局で出ることを前提にしない）。
- [ ] 結果画面で完成数式・役・得点・累計点が読める。
- [ ] 「次の局へ」で進行し、親が移動。複数局でも画面が崩れない。
- [ ] ホームインジケーター、アドレスバーの表示／非表示、スクロール時も手牌やボタンを押せる。
- [ ] 誤ってページをリロードした場合の挙動が明確（継続保存はVer.0.1未実装でも可）。
- [ ] 可能なら縦横回転、別のスマホ、タブレット・Chromebookも確認。

### ユーザーが主観評価する項目
- 牌の数字と関数が即座に区別できるか。
- 打牌前に考える選択肢があるか。
- チー・ロンのタイミングが分かるか。
- AIの進行速度が速すぎず遅すぎないか。
- 「なぜ和了できた／できない」が分かるか。
- 次の一局を遊びたくなるか。

## 4. Claude → Codex → Claude → 実機の反復

1. Claude Codeは開発時に `feature/...`・`fix/...` のブランチを作成し、原則として **Pull Request** を作る。mainに直接変更を加えない。
2. Claude CodeはPRに、変更目的・関係する仕様・テストコマンドと結果・スクリーンショット・再現シード・既知の制約を記載。
3. Codexは独立監査。まず **`AGENTS.md`** を読み、ベースブランチとの差分と関連コードを調べる。結果は「重大度・根拠・再現手順・推奨対策」でまとめる。
4. **P0（致命的）・P1（高リスク）は原則マージ保留**。Claudeに修正してもらい、Codexが再確認。
5. P2（中）・P3（低）はユーザーの実機所見とともに優先順位を決める。
6. 問題が解消されたらユーザーの承認のもとmainへ反映し、公開テスト版の動作を再確認。
7. 各版の報告を `docs/` または `reports/` に保存し、確定した仕様は `docs/05-decision-log.md` を更新する。

## 5. Codexの優先監査項目

- **数学の値**：49の有効面子、tan90°/270°未定義、象限の符号、根号を含む正確な同値表現。
- **和了**：3面子の完全分解と最も高得点の選択。役なし門前、鳴き後の役必須、九角無双・同角三関・三重同式。
- **状態遷移**：物理牌の保存（山・手牌・河・チー面子）、チーの割り込みと手番、ロン＞チー、アタマハネ、保留チーの取消し、流局。
- **AIの公平性**：他家の手牌・未来の山順の取得がないこと。ロジックの性能。
- **UIと安全性**：iOS Safariのタップ、重複操作、可読性、画面オーバーフロー、GitHub Pagesの相対URL、公開されたデバッグ経路、データ保存の範囲。
- **検証記録**：テストの不足、誤解を招く統計、未実装のフリテン・点棒授受をバグと混同していないか。
