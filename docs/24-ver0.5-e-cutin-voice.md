# 数雀（MATHJONG）Ver.0.5-E（仮）実装記録 — ドラマチック・コール演出＋宣言ボイスの導入準備

作成: 2026-10-27 ／ 基準: main `97a8202`（Ver.0.5-D のマージ）／ ブランチ `feature/v0.5-e-cutin-voice`
版（暫定）：画面 `0.5.0-e`。エンジン `0.5.0-a` は据え置き（ルール・判定・得点・AI・リーチ成立条件・ロン／ツモ判定は変更なし）。
「Ver.0.5-E」は実装側の仮の名前で、正式な版名はオーナーが決める。

> **区別**：この版は「① 演出の実装（完成・監査待ち）」と「② 宣言ボイスの導入準備（音声は未採用）」の2つ。
> ② では**人の声の音声ファイルを1つも組み込んでいない**。オーナーが声を正式採用するまで、宣言ボイスは鳴らず、設定にも出ない。

## 1. 方針
- 画面と音の再生管理だけを変更する。`src/engine`・タイトル画像・6種類の効果音レシピ（音色・長さ・音量）は変更していない。
- 演出も音も、ゲームの記録（`Game.events`）を読むだけ。ゲームの進行（AI の手番・結果画面・精算）は演出を待たない。
- 宣言者は必ず記録の `seat` から決める。

## 2. 演出（① 実装）
### 2.1 長さと段階
| 演出 | 長さ | 最低表示時間（後ろに待つ演出があるとき） | 段階 |
|---|---|---|---|
| チー | 1.0秒（旧0.42） | 0.7秒 | 帯が左から入る（約0.16秒）→ 中央で静止 → 右へ抜ける |
| ポン | 1.2秒（旧0.52） | 0.8秒 | 帯が中央から一気に広がる衝撃 → 3枚が集まる → 静止 → 閉じる |
| リーチ | 0.9秒（旧0.7） | 0.65秒 | 従来の演出（十字の光条・宣言牌）を 0.9 秒に。宣言者の表示を追加 |
| ツモ | 2.0秒（旧1.0） | 短くしない | 冒頭に閃光1回・光の輪 → 中央で静止（〜1.0秒）→ 最上部の小さな帯に替わる → 消える |
| ロン | 2.2秒（旧1.1） | 短くしない | 冒頭に閃光1回・放射状の光条・揺れ → 中央で静止（〜1.1秒）→ 最上部の小さな帯に替わる → 消える |

- 登場を引き伸ばすのではなく、中央で「宣言者・宣言の文字・牌」を読める**静止時間**を取った。
- ロン・ツモは冒頭を強く、後半は中央の大きな表示を消して、画面最上部の小さな帯（「下家 AI-A の ロン！ ＋和了牌」）に替える。眩しさを抑え、**結果画面の内容をほとんど隠さない**（結果画面は従来どおり、和了と同時に開く）。

### 2.2 カットイン（CSS のみ・画像なし）
- 斜めに画面を横切る帯（上下の縁に光のライン、中を流れる光の筋）、大きな宣言文字、牌の強調。
- 色：チー 青緑、ポン 金橙、ロン 赤金、ツモ 青白金（リーチは従来の紫金）。
- 横向き（高さ 460px 以下）では帯の傾きを浅くし、牌を少し小さくして画面に収める。
- 閃光は冒頭の1回だけ（`fx-flash-once`、繰り返さない）。連続した強い点滅はしない。

### 2.3 誰が宣言したか
- 宣言者を大きく表示（22〜40px）：「**対面 AI-B の** / **ロン！**」。AI は席（下家・対面・上家）を色付きの札で添える。自分は「あなた の」。
- 宣言者の席を、宣言の色で1回光らせてから静かに縁取る（自分は手牌の欄、AI は各席の欄）。発光するのは宣言者の席だけ。
- ロン・ツモは結果画面が盤面を覆うため、席の発光は結果画面の下になる。宣言者はカットインと最上部の帯、結果画面の見出しで示す。

### 2.4 演出キュー（短時間で消されない）
- `src/ui/effects.js` に純粋関数 `fxOffer`・`fxAdvance`・`fxEndAt` を追加（状態 `{ current, queue }`）。
- 規則：
  - ロン・ツモ：最優先。すぐ表示し、待っている演出をすべて捨てる。表示中のロン・ツモは後から来た演出で潰さない。
  - チー・ポン・リーチ：表示中の演出があれば待つ。前の演出は「最低表示時間」まで見せてから次へ（待つ演出がなければ全長）。
  - キューは最大2つ（超えたら古いものから捨てる）。待っている間に 2.5 秒より古くなった演出は出さない。
  - 新しい局・タイトルへ戻るとき、表示中・待っている演出をすべて捨てる。
- 宣言の効果音（チー・ポン・リーチ・ロン・ツモ）は、演出が**実際に表示された時**に鳴らす（`fxShow`）。待った演出は表示と同時に鳴り、捨てた演出は鳴らない（演出と音が一致）。打牌音は従来どおり記録の時点。
- ゲームの進行（AI の手番・結果画面）は待たない。

### 2.5 簡易表示・reduced motion
- 帯・閃光・揺れ・牌・席の発光アニメーションを出さない。宣言者と文字を暗い下地の上に、通常と同じ時間表示する（不透明度だけで現れて消える）。
- 席は点滅させず、枠の色だけで示す。ロン・ツモは結果画面を隠さないよう画面上部に出す。

## 3. 宣言ボイス（② 導入の準備・音声は未採用）
### 3.1 音声の制作手段の調査
| 手段 | 商用・公開での利用 | この環境で使えるか |
|---|---|---|
| VOICEVOX（無料の音声合成） | 本体は商用・非商用可、「VOICEVOX:キャラ名」のクレジット表記が必要。キャラごとに規約が異なる（例：青山龍星は企業が関わる利用に事前確認、No.7 は個人の非商用以外は事前確認、もち子さんはゲーム作品を除外）。 | **不可**（配布元の GitHub・公式サイトへの接続がこの環境では拒否される） |
| クラウドの音声合成（Google Cloud Text-to-Speech、Amazon Polly、Azure など） | 各社の利用規約の範囲で、生成した音声をアプリに使えるとする案内がある（要：最新の利用規約の確認）。従量課金。 | **不可**（オーナーのアカウント・課金設定が必要。認証情報はない） |
| ElevenLabs など有料の音声生成 | 有料プランで商用ライセンスが付くとされる（要：最新規約の確認）。 | **不可**（契約・認証情報が必要） |
| 声優への依頼（ココナラ・Skeb 等） | 契約で利用範囲（ゲーム・Web 公開・改変）を決められる。4語だけなので費用は小さい。 | この環境では手配できない（オーナーの判断） |
| Open JTalk（オープンソースの音声合成） | 音声データにより CC BY など | 導入は可能だが**機械的な声**のため、指示どおり代替に使わなかった |

- 結論：この環境では、自然な人の声を作れる手段に接続できなかった。**試聴用の音声ファイルは作っていない。**
- 推奨：(a) 声優に「チー！」「ポン！」「ロン！」「ツモ！」を2方向（低音で迫力／明るく勢い）で依頼する、または (b) オーナーが VOICEVOX をインストールし、商用可・ゲーム利用可のキャラクターで試聴を作る（クレジット表記を設定画面に出せる仕組みは用意済み）。

### 3.2 導入の仕組み（実装済み・音声なしで動作）
- `src/ui/voice.js`（新規）：
  - `VOICE_MANIFEST`：正式採用された音声の設定。**現在は `null`（未採用）**。採用後に `{ id, credit, gain, sfxGain, files: { chi, pon, ron, tsumo } }` を書き、ファイルを `src/ui/voice-<名前>.m4a`（または .mp3）に置くだけで有効になる。
  - `validateManifest`：4種類すべて・決まった場所・形式・音量の範囲を検査。正しくなければ使わない。
  - `createVoicePlayer`：最初の操作（AudioContext の作成）の後に1回だけ4種類を読み込む（同時に呼んでも1回）。`decodeAudioData` の Promise 形式・コールバック形式（古い Safari）に対応。読み込みに失敗した種類は鳴らさず、効果音だけで続く。
- 再生：演出が実際に始まったとき（`fxShow`）に声を鳴らし、そのときだけ宣言の効果音を下げる（既定 0.55 倍）。
- 停止：声も効果音と同じ再生管理（`sound.playBuffer`：音ごとの bus）を通るので、AudioContext の中断・画面が隠れた・ページを離れた・次の局・タイトルで、古い声も確実に切り離される（Ver.0.5-D の P2 修正をそのまま使う）。HTMLAudioElement は使わない。
- 設定：「宣言ボイス オン／オフ」（保存キー `mj-voice`、既定オン）。**採用された音声があるときだけ**設定画面に出し、利用条件の表記（credit）も表示する。
- 開発サーバー（`tools/serve.mjs`）：`src/ui/voice-*.m4a|mp3` だけを音声として配信できるようにした（ほかの場所・名前・形式は従来どおり 404）。

## 5. 未実施・残課題
- **宣言ボイスの音声は未制作・未採用**（3.1）。オーナーの手配・判断が必要。
- WebKit・iPhone Safari 実機：未確認。特に、カットインの重さ・読みやすさ、横向き、ロン後半の帯と結果画面の重なり、`env(safe-area-inset-top)`（ノッチ）での帯の位置。
- 演出の色・長さ・最低表示時間・キューの上限は試作値。オーナーの好みに合わせて調整できる。
- ロン・ツモでは結果画面が盤面を覆うため、席の発光は見えにくい（カットインと結果画面の見出しで宣言者を示す）。
