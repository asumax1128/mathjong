# MATHJONG Ver.0.1 実装仕様・テスト記録

作成: 2026-10-24 ／ エンジン `0.1.0`

人間1人＋AI3人で、三角関数の牌を使った麻雀を最初から最後まで遊べる Web 試作版。
本書の **「暫定採用」** は Ver.0.1 を動かすための仮決定であり、正式決定ではない（[決定ログ](05-decision-log.md) 参照）。
設定値はすべて `src/engine/config.js` にあり、コードを書き換えずに変更できる。

## 1. 構成

| パス | 役割 |
| --- | --- |
| `index.html` | ゲーム画面の入口（静的ファイルのみ・ビルド不要・外部依存なし） |
| `src/engine/config.js` | 牌の枚数、角度の採否（360°）、役・特殊和了の得点、門前限定フラグ、ルール設定 |
| `src/engine/exact.js` | 三角関数の値を `(p/q)·√r` の厳密値で計算（文字列で判定しない） |
| `src/engine/rules.js` | 牌の種類、有効面子49種の生成、和了形の全探索、役判定、特殊和了 |
| `src/engine/game.js` | 1局の状態機械（配牌・ツモ・打牌・チー・ロン・ツモ和了・流局、牌の不変条件チェック） |
| `src/engine/ai.js` | AI（3性格）。公開情報 `viewFor()` だけで判断 |
| `src/ui/` | 画面（表示と入力のみ。判定はエンジンが行う） |
| `tests/*.test.js` | 単体・対局テスト（`node --test`） |
| `tests/e2e/play.mjs` | ブラウザ実操作テスト（Playwright） |
| `tools/simulate.mjs` | AI 4人の自動対戦・統計 |
| `tools/serve.mjs` | 依存なしのローカル配信サーバー |

技術選定: 既存リポジトリにアプリコードがなかったため、**依存ゼロの ES モジュール（素の JavaScript）** を採用。
同じエンジンをブラウザと Node（テスト・シミュレーター）で共有する。GitHub Pages 等の静的ホスティングにそのまま置ける。
旧 Python シミュレーター（`scripts/legacy/`）は参照のみで流用していない。

## 2. ルールの実装状況

### 牌（暫定採用）
- 関数牌 sin/cos/tan 各16枚、角度牌17種×4枚（360°を含む）、結果牌13種×4枚＝**168枚**。
- 360°は `config.angles` の `enabled` で除外可能（除外時 164枚・有効面子46種）。テストで両方を検証済み。

### 面子の判定
- 角度ごとに sin/cos/tan の値を基準角（0/30/45/60/90°）と象限の符号から**厳密計算**し、同じ厳密値を持つ結果牌と対応付ける。
  `1/√2` は内部で `(1/2)√2` に正規化される。tan90°・tan270° は 0 除算として「定義なし」。
- 生成した49面子は docs/02 の値表、および `Math.sin/cos/tan` の数値と自動テストで一致を確認。

### 進行
| 項目 | 実装 |
| --- | --- |
| 配牌 | 親から順に各8枚。親が最初にツモ（9枚） |
| 手番 | 席0（あなた）→1（下家）→2（対面）→3（上家）→0…。親は局ごとに1つずつ移動 |
| ツモ・打牌 | ツモで9枚→和了判定→打牌で8枚 |
| チー | **上家の直前の打牌**で数学的に正しい面子が完成するときのみ。手牌2枚＋打牌で公開面子、ツモせず打牌、次の手番はチーした人の下家 |
| チーの上限 | 2回（暫定採用）。3回目は手牌が0枚になるため不可。その牌で完成する場合はロンになる |
| チー直後の和了 | 不可（暫定採用）。打牌のみ。完成する牌ならロンを宣言すればよい |
| ロン | 他の3人の打牌で和了形が完成する場合 |
| ツモ和了 | 自分のツモで和了形が完成する場合（チー直後は対象外） |
| 優先順位 | **ロン ＞ チー**。複数ロンは**アタマハネ**（打牌者から手番順に最も近い1人）。チーを選んでも、後続の人がロンすればチーは取り消し |
| ロンしない | 次の候補へ。全員見送れば通常進行（進行不能にならないことをテスト済み） |
| 流局 | 山が尽き、最後の打牌に誰も宣言しなかったとき |
| フリテン | **未実装**（Ver.0.1 では見逃し・自分の捨て牌でもロン可） |
| 鳴き後の役 | チーした手は**役が1つ以上必要**。門前は役なしでも通常和了可 |

### 和了形の探索
- 手の内の牌を面子へ分ける方法を**打切りなしで全列挙**（重複は除去）し、全候補の役・得点を計算して最高得点の形を採用する。
- 旧シミュレーターの「最大30件で打切り」問題は再現しない。役のない分割が先に見つかっても、役のある別分割を採用することをテストで確認。
- さらに、ランダムな手2000件で「9枚を3枚ずつに分ける全280通りの総当たり」と得点が一致することを検証。

### 役と仮得点（すべて暫定採用・`config.yaku` で変更可）

| 役 | 条件 | 仮得点 | 鳴き |
| --- | --- | ---: | --- |
| 通常和了 | 3面子 | 1（基本点） | ― |
| 三関制覇 | sin・cos・tan を1組ずつ | +1 | 可 |
| 同関一色 | 3組すべて同じ関数 | +2 | 可 |
| 余角対 | sinθ と cos(90°−θ)（0≤θ≤90°）の2組を含む | +2 | 可 |
| 三象限巡り | 異なる3象限の角度（軸上の角度を含まない） | +2 | 可 |
| 第n象限一色 | 3組の角度がすべて第n象限の内部（同角の重複可） | +3 | 可 |
| 象限三角揃い | 1つの象限の3角度を1回ずつ（象限一色と複合） | +4 | 可 |
| 同値三連 | 3組の結果がすべて同じ | +4 | 可 |
| 同角三関 | 同じ角度で sin/cos/tan 各1組 | 役満 16 | 可（暫定） |
| 三重同式 | 全く同じ面子3組（実際に各牌3枚が必要） | 役満 16 | 可（暫定） |
| 九角無双 | 0°〜180° の角度牌9種を各1枚（特殊和了） | 役満 16 | **門前限定** |
| 裏九角無双 | 180°〜360° の9種（特殊和了） | 役満 16 | **無効**（未承認） |

- 複合：通常役は基本点に**加算**。
- **役満成立時は通常和了点と通常役を加算せず、役満の点のみ**（複数役満は加算）。`config.scoring` で変更可。
- 余角対は「0〜90° の非負角で角度の和が 90°」と定義（docs/03 の「有効な非負角」に従った暫定解釈）。
- 得点は**和了者に加算するだけ**（点棒の授受・放銃者の支払いは未実装）。累計得点を画面に表示。

## 3. AI の仕様

`src/engine/ai.js`。判断に使うのは `Game.viewFor(seat)`（自分の手牌・全員の河・全員の公開面子・山の残り枚数）のみ。
他家の手牌・山の並びは渡されない（テストで確認）。

- **手の評価**：あと必要な面子数 k に対し、k 個の面子の組合せ（重複可、k=3 で 20,825 通り）をすべて調べ、
  「不足牌の枚数（あと1枚の組を最も重視）」「不足牌の見えていない残り枚数」「完成時の仮得点」を掛け合わせた重みの総和を価値とする。
- **打牌**：価値が最大になる牌を捨てる。
- **チー**：チーして最良の打牌をした後の価値と、チーしない場合の価値を比較。チー後の手では**役のない完成形を 0 評価**するため、役の見込みが消える鳴きはしない。
- **和了**：ロン・ツモできれば必ず和了。
- **性格**（`PERSONALITIES`）：
  - 速攻型：得点をあまり重視しない。チー後の価値が現状以上なら鳴く。
  - 役重視型：仮得点の 1.6 乗で評価。チー後の価値が 1.35 倍以上のときだけ鳴く。
  - 門前重視型：チーしない。得点を中程度に重視。
- 強さの調整は `AI_TUNING`（不足牌の減衰率など）と各性格のパラメータで行う。
- 守備（危険牌の回避）は未実装。

## 4. テスト結果（2026-10-24 実行）

### 単体・対局テスト `npm test` — **32件すべて成功**
- 値表（docs/02 と一致・数値検算）、結果牌の正規化、有効面子 49/46 種、168/164 枚の構成
- 正しい面子・不正な面子（符号違い、tan90° など）、象限分類
- 門前役なし和了、チー後の役必須、各役・役満・九角無双・裏九角無双（無効/有効/360°なし）
- 複数分割で最高得点の形を採用、総当たり検算 2000 件
- 配牌枚数、シード再現性、チー後の手牌 6→5 枚と手番、上家以外からのチー不可、
  ロン優先・アタマハネ・チー取消し・ロン見送り、ツモ和了、不正操作の拒否、流局（168 枚の保存）
- AI：ツモ/ロンする、完成面子を崩さない、門前型はチーしない、チー後の役なし形を評価しない
- AI 4人の自動対局 60 局＋360°なし 10 局で、**毎手**牌の重複・消滅・手牌枚数・公開面子の正しさを検査

### ブラウザ実操作テスト `node tests/e2e/play.mjs`
Playwright（Chromium）で、牌をタップ→もう一度タップ（または「捨てる」）、ツモ・ロン・チー・見送るボタンを押して対局。
- 局面テスト：ツモ和了（三関制覇 2点）、九角無双（16点）を画面から宣言し結果表示を確認
- iPhone SE 375×667 / Android 412×915 / iPad 縦 768×1024 / Chromebook 1366×768 で複数局を完走（計 25 局で確認）
- 人間のロン和了、ロン見送り、人間のチー（手牌 −2 枚の確認）、人間のチーが後続のロンで取り消されるケースを確認
- 全端末で横スクロールなし・コンソールエラーなし・毎操作で牌の不変条件 OK

### テストプレイで見つけて修正した不具合
1. AI の評価が 1 手 150ms 程度と遅く、スマホでテンポが悪い → 組合せを型付き配列で事前計算し約 8ms に短縮。
2. 結果画面で「ロン（自分 あなた から）」と表示 → 「あなた から」に修正。
3. 小さい河の牌で `−1/√2` が枠からはみ出す → 河の結果牌の文字サイズを調整。
4. 375px 幅でヘッダーが3行に折り返す → 狭い画面ではバージョン表記を省略。
5. 役満の得点が「+16」と加算表記になる → 役満は加算でないため符号を外した。
6. `=` 記号が薄く読みにくい → 濃く・太く変更。

## 6. 遊び方
- **PC/Chromebook**：リポジトリで `node tools/serve.mjs` → ブラウザで `http://localhost:8080/`
- **スマホ・タブレット**：
  - 同じ Wi-Fi 内の PC で上のサーバーを起動し、`http://<PCのIPアドレス>:8080/` を開く。
  - または GitHub の Settings → Pages で `main` ブランチのルートを公開すると `https://asumax1128.github.io/mathjong/` で遊べる（ビルド不要）。
- 操作：牌をタップで選択、もう一度タップ（または「捨てる」）で打牌。和了できるときは「ツモ」「ロン」、チーできるときは「チー」ボタンが出る。
- 「ヒント」：手牌の完成面子の数と、あと1枚の組合せ数を表示（使用回数を記録）。値表もヒント扱い。
- URL に `?seed=数字` を付けると同じ配牌を再現できる。
