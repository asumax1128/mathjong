# 数雀（MATHJONG）Ver.0.5-B（仮）実装記録 — ロン・ポン・チーの演出

作成: 2026-10-27 ／ 基準: main `b4a927e`（Ver.0.5-A のマージ）／ ブランチ `feature/v0.5-b-call-effects`
版（暫定）：画面 `0.5.0-b`。エンジン `0.5.0-a` は据え置き（ルール・判定・得点・進行は変更なし）。
「Ver.0.5-B」は実装側の仮の名前で、正式な版名はオーナーが決める。

## 1. 方針
- **視覚演出だけ**を追加する。ゲームのルール・判定・得点・AI・進行は変更しない。
- 演出は、ゲームの記録（`Game.events`）を**読むだけ**で発火する。ゲームの状態は変更しない。
- 演出の有無・長さは、進行に影響しない。演出を待たずにゲームは進み、結果画面も従来どおり開く。
- 効果音は今回は入れていない（視覚演出を優先）。
- 軽さ：CSS のアニメーションが中心で、動かすのは `transform` と `opacity` が主。画像・外部ライブラリは使っていない。

## 2. 演出の仕様
| | ロン | ポン | チー |
|---|---|---|---|
| 文字 | 「ロン！」 | 「ポン！」 | 「チー！」 |
| 長さ | 0.80秒 | 0.52秒 | 0.42秒 |
| 色 | 赤〜金の発光 | 金〜橙の発光 | 青〜緑の発光 |
| 動き | 文字が大きく現れて収まる。画面全体に赤〜金のフラッシュ。盤面が軽く揺れる（0.5秒）。 | 文字が収まる。鳴いた3枚が左・上・右から集まる。鳴いた面子が光る。 | 文字と3枚が左から流れる（牌は少しずつ遅れて）。鳴いた面子が青く光る。 |
| 牌 | 和了牌を大きく表示 | 鳴いた面子の3枚 | 鳴いた面子の3枚 |
| 名前 | 和了した人（あなた／AI-A…） | 鳴いた人 | 鳴いた人 |

- 出る場面：
  - ロン：自分・AI のロン和了。
  - ポン・チー：自分・AI の鳴きが成立したとき。ほかの人のロンで取り消されたポン・チー（記録に残らない）では出ない。
  - 自動パスで見送ったポン・チーでは出ない（鳴いていないため）。
  - ツモ和了、リーチ宣言、流局では出さない。
- 文字の大きさは画面の幅に合わせる（`clamp`）。320px でも画面内に収まる（ロン 26vw、ポン 21vw、チー 18vw）。
- 重なったとき：優先度は ロン ＞ ポン ＞ チー。
  - 表示中のロンは、後から来たポン・チーで消さない。
  - 優先度が同じか高いものは、表示を入れ替える。
  - 同時に複数の記録が増えた場合は、優先度が最も高いものだけ出す。

## 3. 設計
- `src/ui/effects.js`（新規、純粋関数のみ。DOM・タイマー・エンジンを持たない）：
  - `EFFECTS`：演出の仕様（文字・長さ・優先度）。
  - `effectKindOf`・`pickEffect`：記録から、どの演出を出すかを決める（同じ記録で2回出さない。別の局は数え直す）。
  - `shouldReplace`：重なったときの扱い。
  - `fxProgress`：再描画の後に、アニメーションを続きから再生するための経過時間。
  - `parseEffectMode`・`isLiteEffect`：簡易表示の設定。
- `src/ui/app.js`（演出レイヤーの管理）：
  - **専用レイヤー `#fx-layer`**：`#app` の外（`body` 直下）に置く。`render()` が `#app` の中身を作り直しても演出は途切れず、`pointer-events: none` でタップを通す。
  - `fxScan()`：`step()` の先頭で呼ぶ。ゲームの記録に新しいロン・ポン・チーがあれば発火する。状態の変更はしない。
  - `fxFire()`：演出を出す。`fxClear()`：新しい局・タイトルへ戻る・演出の終了で消す（タイマーも止める）。
  - `fxApply()`：盤面の演出（ロンの揺れ・ポン／チーの面子の発光）を付け外しする。再描画で要素が作り直されても、経過分だけアニメーションをずらして続きから再生する（やり直さない）。
- 画面の揺れは `.table` だけにかける。固定配置の操作バーや、重ねて表示する結果画面は揺らさない。
- 簡易表示（設定：「ロン・ポン・チーの演出」→「簡易（文字だけ）」、保存キー `mj-effects`＝`'lite'`）：
  - 文字だけ。フラッシュ・揺れ・牌・発光を出さず、不透明度だけで現れる。
  - OS の「視差効果を減らす」（reduced motion）でも、同じ簡易表示になる。
  - 設定を変えても、表示中の演出は変わらない。次の演出から反映する。
- 開発用（ローカルだけ）：`window.__mathjong.fx` に `fire`・`clear`・`scan` を出した（E2E 用）。公開サイトでは無効。

  - 同じ記録で2回出さないこと、別の局は数え直すこと。
  - 重なったときの入れ替え（ロンを潰さない）。
  - 簡易表示の設定。
  - 数学Ⅰ・Ⅱの AI 対局24局で、演出の判定を行っても記録・結果が変わらないこと。
  - 構造（レイヤーがタップを通す、`effects.js` がエンジンを読み込まない、`fxScan` が状態を変更しない）。
- E2E `v05bEffects`（7項目）：
  - 自分のポン・チー：文字・3枚・面子の発光、終わると消える、演出中もヒントと自動パスの切替ができる、記録が増えない。
  - 自分のロン：文字・和了牌・フラッシュ・揺れ、結果画面と精算（親ロン 6B）が従来どおり、次の局へ持ち越さない。
  - AI のロン・ポン：AI の名前を表示。
  - 重なり（チー→ポン→ロン→ポン・チー）：ロンを潰さず、進行・記録が不変。新しい局・タイトルへ戻ると演出を消す。
  - リーチ中のロン（リーチ＋1 は従来どおり）、自動パス ON でもロンは出る、自動パスで見送ったポンでは演出なし。
  - 簡易表示と reduced motion。
  - 320／375／430px：演出が画面内に収まる、文字の大きさ、横スクロールなし。
- 既存の検査は、版の表記（0.5.0-b）だけ更新した。

## 4.1 Codex 監査 P2-1 の修正（演出中に「通常／簡易」を変えたとき）
- **不具合**：演出中に設定の「通常／簡易」を変えて画面を再描画すると、表示中の演出の一部だけが新しい設定になった。
  - `fxFire()` は演出の開始時の設定で、文字・牌・フラッシュ（レイヤー）を作る。
  - 一方、`fxApply()` は再描画のたびに、現在の設定を読み直して、盤面の揺れ・面子の発光を付け外ししていた。
  - 開始時のモードが `S.fx.current` に保存されていなかったため、通常で始まったロンは、簡易に変えると文字・フラッシュは通常のまま揺れだけ消え、簡易で始まったロンは、通常に変えると文字は簡易のまま途中から盤面が揺れた。
- **修正**（`src/ui/app.js`、約12行）：
  - `fxFire()` で、通常／簡易の実効モード（設定＋OS の reduced motion）を**1回だけ**決め、`S.fx.current.lite` に保存する。
  - 文字・牌・フラッシュ（`fxHTML(kind, ev, lite)`）、レイヤーのクラス、盤面の揺れ・発光（`fxApply` が `c.lite` を見る）は、すべてその保存値を使う。
  - 現在の設定を読み取る `fxLite()` の呼び出しは、`fxFire` の1か所だけになった。
  - 設定を変えても、表示中の演出は終了まで変わらない。次に始まる演出から、新しい設定が反映される。
  - OS の reduced motion も開始時の判定で簡易に反映する。開始後に変わっても、表示中の演出は変えない。
- 変更していないもの：`src/engine`・`tools`、演出の長さ・色・文字・動き、ゲームのルール・得点・AI、リーチ・オートパスの仕様。画面版 `0.5.0-b`・エンジン版 `0.5.0-a` も同じ。
- **回帰テスト**（修正前の `0766998` で失敗し、修正後に合格することを確認した）：
  - E2E `v05bFxModeFixed`（4項目）：
    - ロン・ポン・チーのそれぞれで、通常 → 簡易 と 簡易 → 通常。演出中に設定を変えて閉じる（再描画）と、表示中の演出（レイヤー・フラッシュ・和了牌・3枚・揺れ・発光）が変わらず、同じ演出が続くこと。次の演出は新しい設定になること。
    - reduced motion を開始時の判定で簡易に反映し、開始後に OS の設定が変わっても表示中の演出が変わらないこと。
    - 設定変更・再描画のあとも、開始時刻と経過（続きから再生）が維持され、元のタイマーで終了すること。
    - 重なり（ロン＞ポン＞チー）、新しい局での消去、設定の保存と再読み込みが従来どおりであること。
  - 単体テスト（`tests/effects.test.js` に1件）：実効モードを開始時に1回だけ決めて保存し、レイヤー・揺れ・発光が保存値だけを使う構造であること。
  - 修正前の確認：
    - 症状の再現：通常 → 簡易で `shake` が 1 → 0、簡易 → 通常で 0 → 1 になり、レイヤーと食い違った。修正後は変わらない。
    - E2E は、修正前のコードで失敗した。保存項目だけを足した状態でも、症状の検査（揺れ・発光が続くこと）で失敗した。単体テストも修正前に失敗する。
