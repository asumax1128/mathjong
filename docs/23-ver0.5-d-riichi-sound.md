# 数雀（MATHJONG）Ver.0.5-D（仮）実装記録 — リーチ演出・効果音・ロン演出の強化

作成: 2026-10-26 ／ 基準: main `c9beec6`（Ver.0.5-C のマージ）／ ブランチ `feature/v0.5-d-riichi-sound`
版（暫定）：画面 `0.5.0-d`。エンジン `0.5.0-a` は据え置き（ルール・判定・得点・AI・進行は変更なし）。
「Ver.0.5-D」は実装側の仮の名前で、正式な版名はオーナーが決める。

## 1. 方針
- **画面と音だけ**を追加・変更する。`src/engine`・`tools`・ルール・得点・AI・進行は変更していない。
- 演出も音も、ゲームの記録（`Game.events`）を**読むだけ**で発火する。状態は変更せず、進行を待たない（再生できなくても、ゲームは同じように進む）。
- 1つのゲーム上の出来事に、演出・音は**それぞれ1回**。演出と音は同じ記録の件数（`seen`）で二重化を防ぐ。
- 効果音は**音声ファイルを使わない**（Web Audio による自作の合成音だけ）。配信は増えず、権利の問題もない。

| 打牌 | 約0.09秒 | 短く硬い牌の接触音（ノイズの打撃＋短い「コツ」）。一番多く鳴るので控えめ |
| チー | 約0.22秒 | 軽快な二音の上昇と高音の粒 |

| ロン | 約0.95秒 | 中域の爆発と衝撃、鋭い和音、遅れて来る二度目の衝撃 |

- 実装は `src/ui/sound.js`。音は「声（オシレーター／ノイズ＋フィルター＋音量の包絡）の並び」（レシピ）で表す。雑音は決まった式で作る（乱数を使わず、毎回同じ音）。
- 出力は 全体音量 0.55 → 圧縮器 → 出力。圧縮器で合算が割れないようにしている。
- 音量の釣り合い（実測・OfflineAudioContext）：ピークは打牌0.27〜ツモ0.63、最大/最小 4倍以内。決着の音（リーチ・ロン・ツモ）を大きく、打牌を控えめにした。

### 3.2 鳴らす規則
- 優先度（同じ回に複数の記録が増えたとき、1つだけ鳴らす）：ロン・ツモ ＞ リーチ ＞ ポン ＞ チー ＞ 打牌。
- リーチの記録は宣言牌の打牌の記録より前にあるので、宣言牌の打牌音は重ならない（リーチ音だけ）。
- 牌を引く・流局では鳴らさない。
- 記録の件数（`S.sound.seen`）で、同じ記録を2回鳴らさない。別の局は数え直す。再描画・`step()`・設定の開閉では鳴らし直さない。
- 新しい局・タイトルへ戻るときは、鳴っている音を短く絞って止める（`silence`）。

### 3.3 iPhone Safari の再生制限への対応
- AudioContext は**最初の操作（touchend／pointerup／click／keydown）まで作らない**。操作の中で作って `resume()` し、無音の1サンプルを再生して許可を確実にする。受け身（passive）・捕捉（capture）で聞くだけなので、タップ・スクロール・ドラッグの挙動は変えない。
- 以後も、止まっていれば（suspended／interrupted：着信・バックグラウンド・マナー切替など）操作のたびに `resume()` を試す。
- 再生は**待たない・例外を出さない**。context が running でなければ、その音は鳴らさず（遅れて場面とずれるため）無音で戻る。AudioContext がない・作れない環境でも同じ。
- 設定画面で「オン」にした操作の中でも再生を許可する。
- 注意：iPhone のマナースイッチ（サイレント）では、Web Audio が鳴らない端末・設定がある。設定画面に注記を入れた。

### 3.3.1 中断した音を復帰後に鳴らさない（Codex 監査 P2 の修正）
- **不具合**：AudioContext が suspended／interrupted になると `context.currentTime` が止まり、予約済みの音の「続き」が復帰後に鳴った。AI のリーチ音の開始から約0.1秒で suspend し、画面のリーチ演出（0.7秒）が終わるまで待ってから操作で resume すると、終わったはずのリーチ音の後半が遅れて出た（音と画面が一致しない。ゲーム進行には影響しない）。
- **原因**：音は `AudioContext` の時刻に予約するだけで、止まったことを知る手段も、古い音を取り消す手段もなかった。
- **修正**（`src/ui/sound.js` の `createSoundPlayer`、`src/ui/app.js` にリスナー2行）：
  - 音ごとに専用の出力（bus）を作り、全体の出力の連鎖（音量 → 圧縮器 → 出力）につなぐ。
  - 止まったことを知った時点で `drop()`：すべての bus と、全体の連鎖（圧縮器を含む）を丸ごと切断する。古い音源は何にもつながらないので、復帰しても聞こえない（圧縮器の内部に残った数 ms 分も出さない）。復帰後の新しい音は、新しい連鎖につなぐ。AudioContext は作り直さない。
  - 止まったことを知るきっかけ（`drop` を呼ぶ場所）：
    1. `statechange`（context ごとに1回だけ登録）で状態が running 以外になったとき。
    2. `unlock()`・`play()` が、止まった状態を見つけたとき（`resume()` を試みる**前**に切り離す。イベントを受け取れなくても漏れない）。
    3. 画面が隠れた（`visibilitychange` で `document.hidden`）・ページを離れた（`pagehide`）。iPhone のバックグラウンド移行は running のまま音だけ残ることがあるため。リスナーは1回だけ登録。
    4. 各 bus は「音の長さ＋0.25秒」の実時間（`setTimeout`）でも切断する。context の時刻に頼らないので、止まったことに気づけなくても、終わった音は再び鳴らず、bus も溜まらない。
  - `silence()`（次の局・タイトル）は、止まっている context では絞る処理が進まないので `drop()` で切断する。動いているときは従来どおり0.03秒で絞ってから外す。
  - 中断中に要求された音は予約せず（`blocked`）、復帰後にも鳴らさない。新しいゲームイベントの音は、復帰後に通常どおり鳴る。
  - 変更していないもの：6種類の音のレシピ（音色・長さ・音量）、設定・保存、`soundScan`・`pickSound`、ゲームの進行。

### 3.4 設定
- 設定画面の演出の項目は「**視覚演出**」（通常／簡易（文字だけ）。Ver.0.5-D 監査 P3 で「ロン・ポン・チーの演出」から改名。リーチ・ツモも対象のため。保存キー `mj-effects` と動作は不変）。
- 設定画面「効果音：オン／オフ」。保存キー `mj-sound`（`'0'` のときだけオフ。未保存・異常値・保存不可はオン）。
- オフのときは、AudioContext を作らず、声を1つも予約しない。オンとオフでゲームの記録（進行・結果）は完全に同じ。

### 3.5 音源と権利
- **外部の音源・サンプル・音声ファイルは一切使っていない**。すべて本リポジトリの `src/ui/sound.js` が実行時に合成する（権利の問題なし）。
- 音声ファイルの追加がないので、配信サイズ・サブパス・キャッシュへの影響もない。

## 6. 未実施・残課題
- **iPhone Safari 実機：未確認**。次の点を実機で確認してほしい。
