# 数雀（MATHJONG）Ver.0.4-A 実装記録 — 対局システム

作成: 2026-10-25 ／ 基準: main `b6e7757113cbb280d4da130ee7281f7594cefcc4`（Ver.0.3-B）／ ブランチ `feature/v0.4-a-match`
画面 `0.4.0-a`（暫定）・エンジン `0.3.0-a`（1局の判定・AI は変更なし）。点数配分は試作段階の暫定値。

## 1. タイトル画面
- 仮タイトル「数雀（MATHJONG）」を HTML・CSS で表示。正式ロゴは `.title-logo` の中身を画像に差し替える。
- 選択：数学Ⅰ／数学Ⅱ、4局戦（東1〜東4局）／8局戦（東1〜南4局）、AI難易度 初級／中級／上級。
  - AI難易度は保存と表示だけ。初級・上級は「準備中」と表示し、どれを選んでも中級（これまでの AI）で対局する。最終結果にも「（準備中・中級のAIで対局）」と表示。
- 選択は localStorage に保存（`mj-mode`・`mj-length`・`mj-ai`）。「対局開始」で確定。
- `?seed=` のある URL（再現・テスト）はタイトルを飛ばしてその局から始める。それ以外はタイトル画面から。
- 対局中は設定の「タイトルへ戻る」（確認あり）で試合を終了してタイトルへ。

## 2. 局・親・連荘（`src/engine/match.js`、純粋関数）
- 親番 `hand`（0＝東1局 … 7＝南4局）、その親番での連荘回数 `renchan`、実施局数 `played`、試合全体の連荘回数 `renchanTotal`。
- 親の席は `dealerOf(m) = (startDealer + hand) mod 4`（東1局の親は自分）。
- 親がロン・ツモで和了 → 連荘（同じ親番をもう一度）。子の和了・流局 → 親交代（次の親番）。
- 4局戦は東4局、8局戦は南4局の親番が終わったら試合終了。最終の親の連荘中は延長される。
- 積み棒（本場の加点）は導入しない。ヘッダーに「東1局」「連荘n」を表示。

## 3. 親子の精算（B＝既存の和了点。役・役満の計算は変更しない）
| 和了 | 和了者 | 支払い |
|---|---|---|
| 子ロン | +4B | 放銃者 −4B |
| 親ロン | +6B | 放銃者 −6B |
| 子ツモ | +4B | 親 −2B、ほかの子 各 −B |
| 親ツモ | +6B | 子3人 各 −2B |
| 流局 | — | 移動なし |
- 開始は各100点、合計は常に400点。負点でも続行。
- 局の結果画面：精算の説明・局前／増減／持ち点の表（4人）・連荘または親交代（次の局と親）または試合終了。

## 4. 試合終了リザルト
- 最終順位（同点は同順位：例 1,2,2,4）、4人の最終得点、開始100点との差、和了回数、最高和了（1回の和了で得た点と、その和了点B）、実施した局数、連荘回数、数学モード・局数・AI難易度。
- 「もう一度遊ぶ」（同じ設定・新しい山）、「タイトルへ戻る」。

## 4b. 設定の採用元（監査 P2-1）
- 試合の設定（数学モード・局数・AI 難易度）は `startMatch({ settings })` に明示して渡し、試合開始時に `S.matchSettings` へ確定する。
  - タイトルの「対局開始」・設定画面の「新しい対局」：タイトル／設定で選んだ値（予約中の `S.nextMode`・`S.length`・`S.ai`）。
  - 「もう一度遊ぶ」：終了した試合の `S.matchSettings`。予約中の次回用モードやタイトルの選択は使わない（予約は保持される）。seed・持ち点・局数・連荘・和了回数・履歴・ヒントは初期化。
- 最終結果の AI 難易度も `S.matchSettings` から表示する。

## 5. 再現情報・互換
- 山は従来どおり `seed` と局の通し番号 `round` で決まる（`seed + round × 7919`）。連荘で局番号から親が決まらないため、親の席・親番・連荘回数・局数も URL に含める：
  `?seed=S&round=n&dealer=d&hand=h&renchan=r&len=4|8&mode=math1|math2`（持ち点は再現しない）。
- 従来の `?seed=S&round=n` だけの URL：親は (n−1) mod 4（従来と同じ）、親番は n−1（局数の範囲に丸める）。従来と同じ山・同じ親で始まる（E2E で確認）。
- 値の範囲（監査 P2-2）：`src/ui/params.js` の `MAX_SEED`（999,999,999）・`MAX_ROUND`（1,000,000）・`MAX_RENCHAN`（MAX_ROUND − 1）を、読み取りと試合進行の両方で使う。通し局数が `MAX_ROUND` に達したら試合を終える（連荘中でも）ので、ゲームが出力する `round`・`renchan` は必ず読み取りの範囲内。山の seed（`seedBase + round × 7919`）は最大でも約8.9×10⁹で、安全な整数（2⁵³）より十分小さい。負数・小数・指数・空白・非数値・範囲外は拒否して無視（連荘99→100・局数999→1000のような有効な値は往復できる）。
- 再現情報の注意書き（監査 P3-1）：「このURLでは山・配牌・親・局状態を再現します。持ち点や過去の対局履歴は復元されず、全員100点から開始します。」を設定・局結果の再現情報に表示。
- テスト用フック `goRound(n, dealer)`（ローカルのみ）：通し第 n 局を指定の親で始め、試合の状態も合わせる。
