# あおと改善案の比較研究（研究専用・判定なし）

> 状態：**研究専用 Draft PR**（ブランチ `research/aoto-improvement-variants`。PR #64 の研究ブランチの上に作成）。**本番の AI・エンジン・UI は変更しない**（CI で `src/` と `index.html` に main との差分がないことを確認）。mainマージ・Pages公開はしない。**統計的な採用判断はこの PR では行わない**。数値の評価は Codex の独立評価に委ねる。

## 背景（PR #64・docs/69）
あおとの敗因：
- 役のない鳴き：鳴いた手の聴牌の 77〜85% が役なし。
- 40% の雑な打牌：聴牌を保つ打牌の選択率は 44〜48%。

反実仮想「鳴かない」「雑な打牌なし」で、どちらも 1位率が上がった。今回は、あおとの個性（鳴き好き・雑さ）を残す改善案を比べる道具を作る。

## 条件（`tools/research-aoto-variants.mjs`）
本番のあおとの判断（`decideCharacter`）を先に求め、その後で研究用の規則で差し替える。乱数の使い方は本番と同じで、差し替えたときだけ行動が変わる。

| 条件 | 内容 |
|---|---|
| **A** | 現行（本番の判断そのまま）。差し替えのない試合と完全一致することをテストで確認 |
| **B1・B2・B3** | 役を狙える鳴きだけ許可。数字は「あと何枚以内」の上限。下の「B の規則」を参照 |
| **C** | 聴牌を維持する打牌を優先し、それ以外の雑さは保持。下の「C の規則」を参照 |
| **D1・D2・D3** | B（同じ上限）と C の併用 |

**B の規則**（PR #65 監査 P2-1 で修正）
- 本番がポン・チーを選んだとき、**その鳴きだけを適用した仮想局面**（鳴いた面子を公開面子に加え、手牌から2枚を除いた局面）で評価する。
- 鳴いた手として役のある和了形（公開面子＋残りの面子。`rules.evaluateMelds(…, closed=false)` が `hasYaku`）を全組合せ列挙し、手牌に足りない牌の枚数の最小値（鳴いた後に1枚捨てるので最小1）が上限 N 以内なら鳴く。N は B1/D1＝1、B2/D2＝2、B3/D3＝3。
- 足りない牌は、自分から見えていない残り枚数（公開情報）を超えない組合せだけを数える。
- 鳴く確率（ポン 85%・チー 75%）は本番のまま。
- 旧実装（監査時 HEAD ea37581）は `yakuCandidates()` の通常経路と鳴き経路を合わせて評価しており、有効な鳴きを見落としていた（下の「監査対応」）。

**C の規則**
- 本番の打牌（40% の雑な打牌を含む）が、聴牌になる捨て牌があるのに聴牌を崩すときだけ差し替える。差し替え先は、聴牌になる捨て牌のうち、自分から見えていない残り枚数（公開情報）が最も多いもの。
- 聴牌にならない局面の打牌は本番のまま（雑さを保持する）。
- リーチの宣言は本番と同じ `riichiDecision`（初級）。

### 情報の公平性
- B・C が使う情報：自分の手牌・公開面子・全員の河・ドラ表示牌（`viewFor`）、エンジンの `riichiOptions` / `waitsOf`（自分の手牌）、役の判定表（`rules`）。
- 他家の手牌・山の並び・未来の牌は使わない。テストで、他家の手牌と山を入れ替えても判断が同じことを確認した（B 20件以上・C 500件以上の局面）。

## PR #65 監査対応（監査時 HEAD ea37581）
| 指摘 | 重大度 | 対応 |
|---|---|---|
| B の `yakuCandidates()` が通常経路と鳴き経路を合わせて評価し、有効な鳴きを見落とす | P2 | 上の「B の規則」に変更。旧方式は `callKeepsYakuLegacy` として比較用に残す。別実装（`yakuCandidates` に鳴いた後の view を渡す `callYakuDistanceByHint`）とも距離が一致することを全候補で確認 |
| E2 で `agents.filter()` により席番号がずれ、かなたが本物のあおとの河を読めない | P2 | `decideCharacter` の `seatIds` を本番と同じ4席の配列にし、代理の席は `human` とした（`tools/research-beginner-loss-diagnostics.mjs` の `playMatch`）。E2 をすべて再計算 |
| 鳴きの選択と成立が混ざっている。ロン優先で取り消された鳴きも数えている | P2 | 「選択」（chosen）と「成立」（made）を分けた。下の「鳴きの計測の定義」 |
| 試合ごとの記録がない。ペア差の区間がない | P3 | 試合ごとの記録（JSON の `records`・CSV）を保存。同じ seed を1クラスタとしたペア差の 95% CI |

### 鳴きの計測の定義（P2-3）
- **機会**：自分に `pending()` がチー（またはポン）の選択肢を示した回数。
- **選択**（`chi`・`pon`：選択／機会）：その機会に自分がチー（ポン）を選んだ回数。
- **成立**（`chiMade`・`ponMade`）：局の終わりに、自分の公開面子として実際に成立していたチー（ポン）の数。ロン（アタマハネを含む）が優先されて取り消された鳴きは数えない。`cancelled`＝選択－成立。
- **鳴いた局**（`roundsWithCalls`）：成立した鳴きが1つ以上ある局の割合（分母：参加した局）。和了率 鳴き／門前も成立で分ける。
- **鳴き聴牌の役なし**（`yakulessTenpaiCalled`）：観測するのは自分の打牌の直後。成立した鳴き（チー・ポン）を持ち、聴牌している時点を一度でも経た局が分母。そのうち、聴牌時の待ちで和了できない（役なし）時点が一度でもあった局が分子。暗槓だけの局は含まない。
