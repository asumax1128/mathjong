# MATHJONG 開発ロードマップ（企画 → 遊べる試作 → 対戦版）

作成: 2026-10-24  
対象リポジトリ: `asumax1128/mathjong`  
状態: **開発計画（提案）**。新しいルール・期日をユーザー承認なく「正式決定」にしない。

## 0. 目的と最優先方針

目指すのは「三角関数の値を正しく覚えるほど有利で、4人の駆け引きが楽しい麻雀風ブラウザゲーム」。
ただし学習教材の体裁より、**もう一局遊びたくなる競技性**を優先する。

1. **小さく遊べるものを早期に作る。** 仕様を永遠に議論せず、試作→プレイ→数値検証→改修を反復する。
2. ルール判定は画面から分離し、同一エンジンをプレイ版とシミュレーターで共有。
3. 数学的に有効な式・牌消費・手番・和了・得点を**テスト可能な純粋ロジック**にする。
4. 旧シミュレーションを参考にしつつ、既知の問題（和了形30件打切り等）は新エンジンで再実装する。
5. **フェーズごとに採否を決める**。未決定の360°などはパラメータ化して比較できるようにする。
6. 本格オンライン4人戦は、**人間1人＋AI3人の実機プレイが成立した後**に進める。
7. シミュレーションは「誰かが和了した率」のみでなく、戦略別勝率・得点・放銃・所要巡数・役の多様性を測る。

## 1. 現在地（2026-10-24）

### 明確な方向性
- 4人対戦、三角関数の値を3枚（関数・角度・結果）で構成する面子。
- 第1〜第4象限を扱う。角度の表記は度数法。
- 上家からのチー、他家からのロンを採用。ポン・等号リーチ・単独「×」牌はなし。
- チーをした人は有効役が必要。門前は役なしの通常和了を認める試験モデル。
- 9角度 `0,30,45,60,90,120,135,150,180` からなる特殊和了を検討。
- 第n象限一色、同関一色、三関制覇、同角三関、三重同式などを検討。

### 有力な試作パラメータ（**正式確定ではない**）
- 手牌8枚→和了9枚、3面子構成。
- 関数牌 sin/cos/tan 各16枚、角度各4枚、結果13種各4枚。
- 360°を含む17角度なら **168枚山／有効面子49種類**。
- 360°不採用なら16角度、**164枚山／有効面子46種類**（関数各16枚の場合）。
- 旧試験: 関数各12枚156枚山 vs 各16枚168枚山、それぞれ2,500局。平均捨て牌数約27.79 vs 27.61。**この差だけでは優劣を判断できない**。
- 360°の採否、裏九角無双、点数体系、役満の鳴き可否は未決定。

## M0｜最小ルールを決める（最初に着手）

**目標:** 実装者が推測しなくても同じ判定を返せる状態。

- [ ] 360°を入れる/入れないを、設定切替で比較できるよう定義する（正式採否はプレイ後でも可）。
- [ ] 関数各16枚・角度各4枚・結果各4枚を **試作標準** として置くか決める。
- [ ] 9枚の完全分割を通常和了とすることを再確認する。
- [ ] チーは上家の直前の打牌から完成面子を作る場合のみ。公開面子を確定し、手番・打牌・残り手牌の動きを文章化。
- [ ] **ロン・チー同時発生時はロンを優先**する案を検討。
- [ ] チーで最後の面子が完成するケース（捨て牌なし和了を認めるか）を決める。
- [ ] フリテン、複数ロン、流局条件を試作段階でどう簡略化するか明記する。
- [ ] チー後は役必須、門前は役なしOK。特殊和了は基本的に門前限定とする**案**を用意。
- [ ] 役と役満について「和了可否への影響」と「仮点数」を分離する。

**完成条件:** 具体例20ケース以上で、和了・チー・ロン・役・流局について迷いがない。

## M1｜数学とゲーム進行のエンジン

**先にロジック、後から演出。** Python既存コードのロジックは監査対象。Web版ではJavaScript/TypeScript等でUIから独立した同一ルールエンジンを推奨。

- [ ] 17角度×3関数の値表（tan90°, tan270°は不可）から有効面子49種を生成。16角度モードでは46種。
- [ ] 数値の表記を正規化（`1/√2` と `√2/2` は同値）。
- [ ] 168枚の山と、可変枚数の検証。実在しない牌を使って和了できないよう在庫制約を検査。
- [ ] 3面子への分解は**打切りなしで完全列挙**し、複数の完成方法がある場合の役取りこぼしを防ぐ。
- [ ] 同角三関、三重同式、象限一色、三関制覇、余角対、同値三連等を判定。
- [ ] 特殊和了「表・九角無双」を通常和了と別アルゴリズムで判定。裏版は360°次第。
- [ ] 4人の配牌、山、捨て牌、公開面子、チー、ロン、ツモ、流局、席順を状態遷移として実装。
- [ ] 自動テスト: 数学表、定義なし、牌枚数保存、和了判定、役の複合、鳴き直後の枚数、ロン優先、九角、同牌3枚など。
- [ ] 保存する試験に乱数シード・エンジンバージョンを含める。

**完成条件:** 単体・対局テストが全通過し、数千局の自動実行で手牌数の破綻や無限ループなし。

## M2｜Webで実際に遊ぶ（早期MVP）

**スコープ:** **人間1名 vs AI3名**。ネット対戦、会員登録、ランキングは最初は不要。

- [ ] 配牌、ツモ、捨て牌、公開面子、河、残り山、手番を表示。
- [ ] 角度の数字・正負・結果牌が小さな画面でも読みやすいタイル。
- [ ] チー可能時の選択、ロン/ツモボタン、役と点数の表示。
- [ ] 初心者向け任意ヘルプ（sin30°=1/2など）。通常の競技モードで答えを自動的に全部見せない。
- [ ] スマホ（375/390/430px）・タブレット・Chromebookで操作可能。
- [ ] **まずデザインよりも1局完走**。実機プレイ後にUI修正点を記録する。

**完成条件:** 1人＋AI3人で複数局を続けて遊べる。画面はみ出し・操作不能・誤和了がない。

## M3｜役と戦略性の本格検証

**役設計の試験区分**

| 区分 | 役候補 | 採用判断 |
| --- | --- | --- |
| 基本役 | 三関制覇 | 鳴きで成立しやすいため点数を低めに試す |
| 中級役 | 同関一色、余角対、三象限巡り | 多彩な選択肢があるか |
| 高級役 | 第1～第4象限一色、同値三連、象限三角揃い | 出現率・効率・点数で調整 |
| 役満候補 | 三重同式、同角三関、表・九角無双、裏・九角無双（未決） | 数学的・牌枚数的に成立するか、専門AIで狙えるか |

重要: **三重同式**は同一三角セット3組、**同角三関**は同じ角度のsin/cos/tan各1組。**九角無双**は指定角度9種類のみの特殊和了。

**検証するAI**
1. 速攻型：面子の完成を優先、チー積極的。
2. 門前型：チーせず、和了可能性を最大化。
3. 役重視型：役の成立期待値と仮点数を考慮。
4. バランス型：和了率と得点期待値を考慮。
5. 役満専門型：表九角無双・同角三関・三重同式など、それぞれ個別に検証。
6. 守備型（後段階）：相手の公開面子・河から危険牌を推定。

**最低限の比較設計**
- [ ] 同じ乱数条件・席順ローテーションで、**各設定少なくとも10,000局**を目標に試験。
- [ ] 12/16/20枚の関数牌、360°あり/なし、チーあり/なし、役点体系を比較。
- [ ] 和了率、ロン/ツモ、流局率、平均巡数、チー頻度、役別出現率を記録。
- [ ] 複数局の点数授受を実装し、勝率・平均収支・順位・放銃率を比較。
- [ ] 偏りが出た場合は**役・得点・鳴き制約**の調整を先に検討し、専用牌の追加を安易に行わない。
- [ ] 「実力70%・運30%」は**企画上の目標**であり、測定方法自体を設計してから評価する。

**完成条件:** 異なる戦略で選択と成績が変わり、少なくとも複数の役を狙う合理的な理由がある。統計結果・ソース・シードをGitHub保存。

## M4｜人によるプレイテスト

- [ ] 少数の初心者・数学が得意な人の両方にプレイしてもらう。
- [ ] チュートリアルの理解、役の分かりやすさ、対局時間、操作ミスを記録。
- [ ] どの牌を切るか迷えるか、危険牌を推理できるか、リプレイしたくなるかを観察。
- [ ] 教育面: 有名角の値と象限の符号を反復プレイで覚えられるか、プレイ前後の小テスト等で検証。
- [ ] プレイヤー個人情報や学校データを勝手に収集しない。テスト対象が未成年なら運用に配慮。
- [ ] 不具合は「発生手順・期待動作・実際の動作・端末」で記録し、修正→再テスト。

**完成条件:** 初めて遊ぶ人が説明を見て自力で1局完走し、明白なルールの破綻がない。

## M5｜4人オンライン対戦

- [ ] まずは**合言葉で入るプライベートルーム**（友人・クラス内のテストにも適する）。
- [ ] サーバー側で乱数・手番・和了・役・点数を確定。クライアントは他人の手牌や山を参照できない設計。
- [ ] ツモ・打牌・チー・ロンの通知順、タイムアウト、通信切断時の復帰を実装。
- [ ] 4端末同時接続で連続対局、同時操作、再接続の試験。
- [ ] 公開マッチ・レート・ランキングは、対戦安定後に評価。

**完成条件:** 4人とも異なる端末から正常に試合でき、途中通信断で状態が破綻しない。

## M6｜公開・長期拡張

- [ ] 安定版の公開、ルール・役図鑑・簡易説明。
- [ ] 大会モード・戦績・ランキングは利用状況と要望で採否判断。
- [ ] 数学Ⅱの恒等式、加法定理、倍角、半角などは、現行の3枚面子と**矛盾しない別モード**も含めて検討。
- [ ] 他分野（平方公式・指数・対数等）は、十分な共通牌を持てると検証できてから導入。


- 役・数学ルール変更 → `docs/01`, `docs/02`, `docs/03`, `docs/05` を同時更新。
- 検証の際は **バージョン、実験条件、局数、シード、結果、限界**を `results/` と `docs/04` に保存。
- 判断待ちを勝手に正式決定しない。ユーザー承認でM0基準を固定する。
- 既存の `scripts/legacy/` は歴史資料として保持し、検証を経ずに本番コードへコピーしない。
- **開発の優先順位は「動く → 遊ぶ → 問題を見つける → 直す」。** 役名・装飾・ランキングを先行させない。
