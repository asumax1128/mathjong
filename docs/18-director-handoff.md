## 1. プロジェクトと関係者

- 正式名：**数雀（MATHJONG）**。三角関数の牌を用いる4人麻雀風・数学学習Webゲーム。FACTOR×FACTOR、AXIOMIAとは**独立**したリポジトリ。
- GitHub：<https://github.com/asumax1128/mathjong>
- 公開ページ：<https://asumax1128.github.io/mathjong/>
- 原則として人間1人＋AI3人、スマートフォン（特にiPhone Safari）でプレイする静的HTML/CSS/JavaScriptアプリ。ビルド不要。Node.js単体テストとPlaywright E2E、対局シミュレータを備える。
- **オーナー（数学教員）**：ルール・優先順位・UI・公開の最終決裁、iPhone実機テスト。
- **ChatGPT**：企画／ゲームデザインのディレクター、仕様決定案、リスク整理、Claude実装指示、Codex監査依頼、監査結果レビュー、GitHub運用。
- **Claude Code**：実装・テスト・シミュレーション・作業報告・Draft PR。**Claude向け実装指示には毎回「Opus推奨」または「Sonnet推奨」を明記**する（複雑な設計やAI＝Opus、限定修正やUI＝Sonnetが目安）。
- **Codex**：Claudeと**別担当の独立コード監査**。モデル指定はCodex向け最新コーディングモデル／High推論推奨。利用できない設定を推測で報告しない。**Claude自身のレビューはCodex独立監査の代替にならない**。
- 正式フロー：最新main→新ブランチ→Claude実装・テスト→Draft PR/HEAD固定→Codex独立監査→必要ならClaude修正→Codex差分再監査→オーナーの許可でmainマージ→**既存GitHub PagesでiPhone実機テスト**→正式承認。
- **実機テスト専用プレビュー環境は作らない。** オーナーが「自分しかテストしないのでmainにアップして実機テストでよい」と明示している。確認済みの作業を不必要に止めたり、プレビュー環境を提案したりしない。
- 変更は既存機能を壊さないことを最優先。採用・仮仕様・未着手・検証中を厳格に区別する。PRのコードだけでなく固定SHAを確認する。実装報告のテスト実績は、Codexが独立実行するまでは**実装者の報告**として扱う。

## 3. ゲームルールの現状

- 数学Ⅰ：度数法、概ね0°〜180°、**124枚**。数学Ⅱ：弧度法、概ね0〜2π、**168枚**。厳密な牌構成・特殊角度・未定義値などは `src/engine/config.js` と `docs/02-tiles-and-values.md` が権威。
- 1人配牌8枚、9枚（3面子）で通常和了。面子：関数牌（sin/cos/tan）＋角度牌＋対応する結果牌による**数式面子**、または同種牌3枚の**刻子**。特殊和了や役満あり。門前は役なしでも通常和了可能、鳴いた場合は役が必要（厳密な役・判定は `rules.js`、`exact.js`、`docs/03-yaku-catalog.md` を参照）。
- チー、ポン、ロン、ツモ。宣言優先順位は**ロン＞ポン＞チー**。アタマハネ、後続ロンによる鳴きの取消しを維持。判定はエンジン `src/engine/game.js` に集約。
- 試合は4人全員**100点スタート／合計400点**、負点続行。親のロン・ツモ和了で連荘、子の和了または流局で親交代。4局戦＝東1〜4局、8局戦＝東1〜南4局。連荘のため実施局数は4/8を超えうる。最終親が連荘する間は継続。積み棒なし。
- **精算（B＝従来の役・和了基本点）**：子ロンは勝者+4B、放銃者−4B。親ロンは勝者+6B、放銃者−6B。子ツモは勝者+4B、親−2B、残る子各−B。親ツモは勝者+6B、子3人各−2B。流局は全員±0。
- 最終順位は同点同順位（例1,2,2,4）。試合終了結果で点数、増減、和了回数、最高和了、実施局数、連荘数を表示。タイトルに数学モード・局数・AI難易度。ロゴは暫定の文字/CSS、**後日正式画像へ差し替え予定**。
- 局の再現URL：`?seed=&round=&dealer=&hand=&renchan=&len=&mode=`。Ver.0.4-Bでは`&ai=`追加。持ち点・過去履歴は復元せず全員100点。旧`?seed=&round=`の山・親の互換を保つ。局状態は `round >= hand + renchan + 1` が必要条件であり完全な履歴の十分条件ではない。上限100万局の安全弁と`endReason`の明示。詳細 `src/ui/replay.js`、`src/engine/match.js`。
- 過去の資料（特にREADME・AGENTS.md）にはVer.0.1〜0.3当時の「開発中」「公開予定」「ロン＞チー」等の古い表記が残ることがある。**最新mainの実装と版別記録、最新PRを優先**。過去の未決定事項（例360°、関数牌数）の試作案を正式仕様と混同しない。

## 4. Ver.0.3-B：2段階ヒント（承認済み）

- ヒントボタンは手牌の下の**「自動整列」の隣**（Ver.0.4-Aで移動）。
- 第1段階「発見」：完成した数式の種類数、あと1枚で完成する組合せ、公開済み面子、狙える役。具体的な数式・手牌のカラー枠は非表示。
- 明示操作で第2段階「確認」：完成数式を一覧、物理牌の利用重複を考慮した同時最大数式面子数を表示。1種類だけなら黄色枠、2種類以上なら赤・青の2式を選択。2色が共有する物理牌は上下に分割した枠。並べ替えでも**物理牌ID**で同じ色を保持。刻子は数式の種類数に含めない。 `src/engine/formulahint.js`。
- 初期の2式は（1）全体の同時最大解に含まれる2式、（2）同時使用可能、（3）共有あり、の優先順。各候補を自由に赤・青へ割当可能。
- 自分の手牌変化では第1段階へ戻す。他家の変化・並び替えでは基本維持。閉じて開き直すと第1段階。局切替では閉じる。
- 回数は発見・確認・値表を別記録。**発見/確認は同一物理手牌状態では重複計上しない**、自動更新は発見回数に加えない。値表は開くたび加算。結果画面に内訳表示。過去局への内訳永続保存は**今回不要**とオーナーが判断。
- PR #8のCodex独立監査・iPhone実機テストともに合格。

## 6. Ver.0.4-B：AI難易度＋ポン自動パス（**実装報告済み・監査前**）

### 6.1 AIの2軸

- 性格：speed（速攻）、value（役重視）、closed（門前重視）。従来の3人に割当。難易度：beginner／intermediate／advanced。全AI3人に同一難易度を適用。
- `decide(game, seat, personality, rng, level='intermediate', info=null)`。4引数の旧呼出は中級として互換性維持する設計。
- **初級**：チー・ポンなし、ロン・ツモは必ずする。完成面子に関わる牌＝残し度4点、あと1枚の面子＝1点。捨て候補の下位3枚を確率60/25/15%で選ぶ。公開の山・河・点数を考慮しない。
- **中級**：既存の`ai.js`判断・乱数・鳴きを同一に維持。旧AIとの固定seedログと旧規則1000局／数学ⅠⅡ各200局の出力一致をClaudeが報告。
- **上級**：中級の手牌評価を土台に不足牌減衰0.22→0.15と、公開情報からロンされる確率・和了見込みをロジスティック推定した攻守期待値を導入。守り係数1.5、数学ⅠⅡ別の係数。鳴き判断は中級と同じ。対戦中に**他家の裏手牌・未来の山を参照しない**。オフライン学習時のラベルには他家の実手牌を使用（実行時とは別）。危険度AUCはClaude報告で数学Ⅰ0.77、数学Ⅱ0.75。持ち点・順位に基づく終盤戦略は**未実装**。
- Claudeの最終報告：数学Ⅰ/Ⅱ×4/8局戦の全4条件で平均順位「上級＞中級＞初級」。上級対中級の平均順位差は-0.12〜-0.19前後で**小さい**、初級は中級相手にかなり弱く1位率3〜5%。異なるseed・席回転・性格を考慮したとの報告だが、**Codexの独立検証が必要**。性能：数学Ⅰ上級1判断平均約5.5ms、数学Ⅱ約24ms（Node側）、初回キャッシュ構築約400ms（数学Ⅱ）、iPhone Safariは未検証。
- 詳細の統計と生データ：PR #10の`docs/17-ver0.4-b-ai-autopass.md`、`docs/data/v04b-levels/`、`tools/simulate-levels.mjs`、`tools/validate-levels.sh`、`tools/summarize-levels.mjs`、`tools/calibrate-advanced.mjs`。
- `&ai=`を再現URLに追加（不正AI指定はエラーへ）、AI速度（画面待ち時間）と難易度は別設定。

### 6.2 チー・ポンのオートパス

- 従来の`mj-chi-autopass`を保持、新たに`mj-pon-autopass`。どちらもlocalStorage値`'1'`のみON、初期OFF。設定2スイッチは**独立**。
- ロン・ツモは絶対に自動見送りしない。優先順位はロン＞ポン＞チーのまま。
- ロン不可でチーもポンも可能な場合：両OFF→両方表示、チーON/ポンOFF→ポンのみ、チーOFF/ポンON→チーのみ、両ON→自動パス。片方だけ可能なら対応するONで自動パス。
- ロン可能時はロンを必ず表示し、自動パスしない。チー・ポンはそれぞれの設定で表示非表示、明示パス操作は残す。
- 宣言が生じた時のスイッチ設定を固定し、宣言中変更は**次の宣言から**。自動処理の重複防止、成功時のみ計上、失敗時は手動選択を復帰、後続他家ロンを阻害しない。
- 通知は「チー／ポン／チー・ポンを自動で見送りました」。次の自分の手番で出し、試合・局跨ぎで持ち越さない。複数見送りはまとめる。
- 宣言ボタン、役候補ヒントの宣言経路、自動見送りは**同一方針**で整合すること。Ver.0.3-Bのヒント計算や色枠は変更しない。
- Claude報告のVer.0.4-Bテスト：**単体209件成功・E2E45項目成功**（headless shellとChromium）。数学Ⅰ/Ⅱ、4/8局、既存23局の回帰も成功とのこと。**未独立監査、Safari未テスト**。
