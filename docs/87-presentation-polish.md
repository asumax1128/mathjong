# 数雀｜演出の追加：一発・役の段階表示・リーチ宣言の席（画面 0.7.4）

表示だけの変更（`src/ui/app.js`・`src/ui/styles.css`）。エンジン（`src/engine`）は無変更で、和了の判定・点数・進行のタイミングは変えない。

## 1. 一発の小さな演出

- 一発が付いた和了の結果画面で、役の一覧の「一発」の行に「一発！」の文字が出て、0.9秒で光って消える（拡大→発光→消える）。
  - カットインや画面全体の演出はしない。
- 門前ツモだけの和了では何も出さない。リーチ・役満などの既存の表示は変えない。
- 光るのは、その行が段階表示で現れた時刻からの1回だけ。再描画で作り直されても、光り直さない（経過分だけ `animation-delay` をずらす）。
- reduced motion では光らせず、「一発！」の文字を静止表示する。

## 2. 和了の役を1つずつ表示

- 結果画面の役の一覧（通常和了・各役・リーチの注記・ドラ）を、1行ずつフェードインする。
  - 1行 250ms。行が多いときは、全体が2秒に収まるよう短くする。
  - 合計の欄は、現れた行までの点の積み上げを見せる。
- 合計の欄の文字は、最初から最終の点のまま（`textContent`・`innerText`）。
  - 途中の値は `::after`（`data-run`）で重ねて見せる。読み上げと既存の E2E は、従来どおり最終の値を読む。
  - 足し上げが最終の点と一致しない形（役満）では、途中の値の代わりに「…」を出す。
- ロン・ツモのカットインが出ているときは、中央の表示が消える時点（長さの約55%）から始める。
  - それまでは、カットインが結果に重なって見えないため。
- 結果画面のどこかをタップすると、残りを一気に全部表示する。
  - ボタン（次の局へ・オンラインの次へ）は段階表示を待たずに押せる。精算画面への遷移も遅らせない。
- 再描画しても最初からやり直さない（局ごとに開始時刻を1つ持つ）。
- reduced motion では、最初から全部を静止表示する。

## 3. リーチ宣言の席の演出

- 宣言した席の名札（卓中央の `.seat-tag`）を、紫〜金の縁で1.0秒光らせる。
- ゲームの記録（`events` の `riichi`）から決める。描画のたびに新しい記録を読む（記録は読むだけ）。
- 既存の宣言の演出（カットイン）のキューとは別に持つ。
  - 続けてロン・ツモがあってカットインを出さなかった場合でも、宣言した席は必ず光る。
- 簡易表示・reduced motion では点滅させず、宣言の直後の1秒だけ縁取る（静止）。
- オンラインのゲスト：ホストが配信する `pub.game.events` は公開情報で、リーチの記録を含む。
  - ゲストの画面はこれを RemoteTable として受け取り、同じ描画の流れで記録を読むので、追加の通信なしで同じように光る。
  - E2E（online-match・online-reconnect）では、ゲストの画面で、宣言のあった席がすべて光ったことを確かめる。
  - 人間どうしの online-long ではリーチが起きないので確かめていない。宣言の件数は試合の進み方によって変わり、0件のこともある。
