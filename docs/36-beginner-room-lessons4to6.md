## 1. 方針（設計 docs/35 からの実装）
- 第4〜6段階は**実際の対局エンジン（`Game`）の4人の局面**で練習する。山は `presetWall`（seed 1）で固定し、毎回同じ局面になる。
- あなたに出すボタン（チー・ポン・ロン・ツモ・リーチ）は `Game.pending()` と `Game.riichiOptions()` が返す実際の選択肢だけ。**偽の宣言ボタンは作らない**。判定・和了・役・点数は既存エンジン（`rules.analyzeWin`・`Game`・`match.settle`／`applyRoundResult`）だけで行い、練習用の判定の複製はない。
- 他の3人は **「練習用CPU」**（9人のキャラクターではない）。台本どおりの公開行動だけをする：自分の番は**ツモした牌をそのまま捨てる**、宣言（ロン・ポン・チー）は**すべて見送る**。CPUは和了しないので、あなたの宣言を横取りしない。CPUは他家の手牌・山の並びを参照しない（ツモした自分の牌を捨てるだけ）。
- 「続ける」ボタンは説明の一時停止を進めるだけの画面の操作で、宣言ではない。
- 数学Ⅰ（度数法・124枚）だけ。
- 通常対局の規則・AI9人・牌の大きさと位置・対戦相手の選択・再戦・再現URL・演出・音声は変更していない。**通常対局に巻き戻し機能は追加していない**（「やり直し」は練習の局面を最初から作り直すだけ）。

## 2. 第4段階：チー・ポン（課題4つ）
| 課題 | 局面（あなた＝席0） | 学ぶこと・確認 |
|---|---|---|
| 4-A チーを体験 | 親は上家。あなた：sin・30°・cos・0°・=1・tan・45°・90°。上家が =1/2 を捨てる | チーのボタンは1つ（`チー：sin 30° = 1/2`）。ポン・ロンなし。チー→公開面子→**ツモせずに**1枚捨てる。「見送る」は練習では実行せず「チーを押そう」と案内 |
| 4-B チーできない場面 | 親は下家。下家→対面→上家の順に =1/2 を捨てる | 下家・対面の =1/2 では**エンジンがあなたに聞かない**（宣言の待ち行列にいない）→ボタンなし・「続ける」で説明。上家の =1/2 でチー |
| 4-C ポン | 親は対面。あなた：sin×2 ほか。対面が sin を捨てる | ポン（上家以外からも可）。チーのボタンはない。sin×3 の刻子を公開して打牌 |
| 4-D 鳴いた後のルール | 親は上家。あなた：sin・30°・tan・45°・=1・sin・=√3/2・135°。上家 =1/2 → チー → 135° を捨てる → 下家 120° → 対面 60° | 120° では sin120°=√3/2 で**形は完成するが鳴いた手で役がない**→ロンのボタンが出ない（`ronAnalysis` が null）。60° なら第1象限一色・象限三角揃いでロン。135° 以外の打牌は練習では止める。完了後に「ロン＞ポン＞チー」「チー・ポンは合計2回まで」「リーチ後はチー・ポン不可」を表示。鳴いた回数 n/2 も表示 |

## 3. 第5段階：リーチ・ロン・ツモ（課題3つ）
| 課題 | 局面 | 学ぶこと・確認 |
|---|---|---|
| 5-A リーチ | 親はあなた。sin 30°=1/2・cos 60°=1/2・tan・45° ＋ ツモ =−1 | 聴牌にならない牌を選ぶと「リーチして捨てる」は押せない（`riichiOptions`）。リーチしない打牌は練習では止める。=−1 でリーチ→=1 待ち（45° でリーチしても可：135° 待ち）。次のツモでは**ツモした牌以外は押せない**（画面）・エンジンも `riichi: tsumogiri only` で拒否 |
| 5-B ロン | 親は下家。あなた：sin 30°=1/2・cos 0°=1・tan・45°（=1 待ち）。下家が =1 を捨てる | ロン（三関制覇 2点）。精算は子のロン：あなた +8・下家 −8。「見送る」は練習では止める |
| 5-C ツモ | 親は上家。同じ手。あなたが =1 をツモ | ツモ（同じ2点）。子のツモ：あなた +8、親 −4、子 −2・−2。捨てる操作は練習では止める。ロンは「捨てた1人が払う」、ツモは「ほかの3人が払う」と結果に表示 |

## 4. 第6段階：卒業試験（1局）
- 親はあなた。配牌 sin・30°・=1/2・cos・0°・=1・tan・135° ＋ 9枚目 90°。**聴牌になる打牌は 90° だけ**（=−1 待ち）。
- 和了の牌 =−1 は **対面の打牌（ロン）→あなたのツモ→下家の打牌（ロン）→あなたのツモ** の順に4回来る（=−1 は4枚すべて）。見送っても次のチャンスがある。
- **自由に打てる**（練習の流れで止めない）。誤りは打った後にヒントで知らせる：聴牌をくずした、リーチしなかった、ロン／ツモを見送った、流局。いつでも「やり直し」で最初の局面から。
- 和了したら、試合の精算（`createMatch` ＋ `applyRoundResult`、親の和了）で点数の移動を表示（合計400点）。例：リーチ→対面からロン＝三関制覇＋リーチ 3点、親のロン +18。
- 「初心者の部屋 修了」と「**実際の対局に挑戦する**」（通常の「対戦相手を選ぶ」画面へ。選択の状態は変更しない）。
- 練習の結果は通常対局の記録・設定に残らない。

## 5. 進み具合の保存・画面
- localStorage の専用キー **`mj-beginner-room-v1`**：`{ v: 1, cleared: [6段階の真偽], resume: { stage, part } }`。版・形の違う値・壊れた値は初期化。読み書きの例外は無視して、画面の記憶だけで動く（「この端末では進み具合を保存できません」を一覧に表示）。ほかのキー（設定・選んだ3人）は読み書きしない。
- タイトルの「初心者の部屋（練習）」：記録がなければ第1段階から（PR #20 と同じ）。記録があれば**段階の一覧**（クリア／途中（課題n/m）／挑戦できる／まだ開いていない）と「続きから」。
- クリアした段階はもう一度遊べる。まだ開いていない段階は選べない。途中の課題から再開できる（課題の途中の局面そのものは保存しない。課題の最初から）。
- 共通のボタン：ヒント／やり直し（今の段階・課題を最初から）／一覧へ／タイトルへ。
- 第3段階の完了ボタンは「第4段階へ進む」（PR #20 では「練習完了・タイトルへ」）。第1〜3段階の「最初から」（第1段階へ戻る）は「やり直し」（今の段階）に変更、「一覧へ」を追加。第1〜3段階の牌・判定・見た目は変更していない。
- 練習の卓：上家・対面・下家・あなたの捨て牌（最後の捨て牌は枠付き、リーチ宣言牌は横向き）、公開面子、親・リーチの表示、山の残り、直前の打牌、あなたの手牌（種類順・ツモ牌は右端の点線枠）。CSS は `.bp-*`・`.br-*` だけを追加（通常対局のスタイルに触れない）。

## 8. 既存ルールについて
- 実装中に既存ルール・エンジンの不具合は見つからなかった（仕様の変更はしていない）。
- 通常対局では、ツモ和了できる9枚でも `riichiOptions` は「1枚捨てて聴牌」の合法な候補を返す。このエンジンの挙動は変更しない。5-C はツモを学ぶ課題なので、ツモ可能な間は「ツモ」だけを表示し、教材が受け付けないリーチ・打牌は表示しない。

## 9. 残る課題・リスク
- 課題の途中の局面（例：チーした直後）は保存しない。再開は課題の最初から。
- 第4・5段階では練習の流れに合わない操作を実行せずに案内する（設計の「誤りはヒントとやり直し」の解釈）。卒業試験は自由。
- 数学Ⅱの練習はない（設計どおり数学Ⅰ先行）。
