# 新ルール①〜④ エンジン実装の記録：王牌・ドラ・暗カン・数学Ⅱ通常ツモ24回

> 状態：**Draft PR #44（未マージ・未公開）**、ブランチ `feature/dora-ankan-cap24`。計画は [docs/59](59-dora-ankan-cap24-implementation-plan.md)。
> 対象はエンジン（①〜④）だけ。⑤の卓UI、Ver.0.7 の画面、Ver.0.8 PR #37 は変更していない。新ルールは `new Game({ ..., newRules: true })` のときだけ有効で、**既定（画面・シミュレーター・既存テスト）は旧ルールのまま**。

## 1. 既存テスト4件の失敗の原因と修正
- 失敗：採用済み28試合の完全一致、追加3人（数学Ⅰ・Ⅱ）の情報公平性・たらの状態復旧、混合難易度の対局（opponents.test.js）。
- 原因（4件とも同じ）：PR が `riichiDecision`（ai.js）を `game.isClosed(seat)` と `game.exposedMelds(seat)` を呼ぶ形に変えた。追加3人の AI には生の Game ではなく公開情報だけの代理（`publicGame`、character-ai-trio.js）が渡り、許可されていない取得は `non-public Game access` で止まる。リーチの判断に入った時点で例外になり、対局が進まなかった。乱数・判断・イベントの変化ではない。
- 修正（テストの期待値は変えていない）：
  - `riichiDecision` は自分の公開ビュー（`viewFor(seat).melds[seat]` の `call`）だけで門前を判定する。旧ルールでは暗カンがないので、従来と同じ条件・同じ `waitsOf(counts)` の呼び出しになる。
  - 旧ルールの形も従来と同じにした：`pending()` は新ルールのときだけ `ankan` を持ち、`viewFor()` は新ルールのときだけ `doraIndicators`・`normalDraws` を持つ（旧ルールではキーも増やさない）。
- 確認：`tools/legacy-equivalence.mjs`（数学Ⅰ・Ⅱ×各150局、3難易度×3性格と12人。AIの全行動・全イベント・結果・公開ビュー）の SHA-256 が main と一致（`17117230…`、300局・14,748イベント）。CI でも main のチェックアウトと比べる。

## 2. ① 王牌・ドラ表示・物理牌の保存（src/engine/dead-wall.js）
- 配牌と親の最初のツモは旧ルールと同じ。その後、通常の山の底（最後に引かれる側）から14枚を王牌に分ける：嶺上牌4枚＋表示候補5組（2枚ずつ）。
- ドラ表示：その組の1枚目が関数牌なら1回だけ2枚目を採用。2枚目も関数牌ならそのまま確定（関数牌ドラも可）。採用しなかった候補は王牌に残る（どこにも移動せず、公開もしない）。ドラは表示牌の次の種類（同じ種類の中で循環。関数 sin→cos→tan→sin、角度は小さい順、値は数値の小さい順）。
- 暗カンのたびに嶺上牌1枚を手牌へ、通常の山の最後に引かれる牌1枚を王牌へ補充（王牌は常に14枚）。嶺上牌は最大4枚＝カンは局全体で最大4回、表示は最大5枚。
- 牌の種類・枚数・物理IDは変えない。`checkInvariants()` は王牌の14枚も数える。
- AI・他家に渡すのは公開された表示牌だけ（`viewFor().doraIndicators`）。嶺上牌・未公開の候補・補充牌は渡さない。
- seed 固定で王牌・表示・対局全体を完全に再現。

## 3. ② 数学Ⅱの通常ツモ24回（game.js）
- 新ルールの数学Ⅱだけ：各席の通常ツモは24回まで（親の最初のツモを含む）。25回目の通常ツモが必要になった時点で流局（山が残っていても）。数学Ⅰは回数の上限なし（山が尽きるまで）。旧ルールは数学Ⅱでも上限なし。
- チー・ポンの後の打牌はツモをしないので数えない。嶺上ツモも別枠（数えない）。河の枚数は制限しない（鳴きで24枚を超えてよい）。判定は「次に通常ツモをする人」ごと。

## 4. ③ 暗カン・嶺上ツモ・カンドラ（game.js）
- 暗カンだけ（大明カン・加カン・槍槓は対象外）。同じ種類の物理牌4枚、自分の手番でツモした直後だけ（`justDrew`。チー・ポン直後は不可）。リーチ中は不可。嶺上牌と通常の山が残っていること。
- 槓子は1面子（`call: 'ankan'`、`kind: 'koutsu'`、4枚の物理IDを保持）。和了は既存の9枚・3面子のまま（槓子の4枚目は面子の外の余り扱いにならない）。手牌は 9→5→嶺上で6枚。
- 暗カンは門前のまま（`isClosed`）：門前限定役（三暗刻）・リーチ・役なしの門前和了ができる。鳴いた手の「役が必要」は暗カンだけなら適用しない。
- 暗カンの後：嶺上ツモ（`justDrew`、嶺上での和了も可）、カンドラを1枚公開。イベント `ankan`・`rinshan`・`dora` を記録。
- チー・ポンの合計2回の上限は、暗カンも面子として数える（暗カン1回＋鳴き2回では手牌が足りなくなるため。物理的に必要）。

## 5. ④ 和了・得点・AI
- ドラは役にならない（和了の判定は既存の `analyzeWin` のまま）。通常和了だけ、ドラ1枚につき＋1点（暫定）：和了者の手牌・公開面子・槓子の牌のうち、公開されたドラの種類の枚数。役満には加えない（役満の点は不変）。`result.points` に含まれるので、親子の精算・合計400点は既存の `settle` のまま。
- AI：すべての AI（3難易度・9人・追加3人）の入口で共通の基準戦略 `ankanDecision` を先に判断する。乱数を使わず、自分の手牌と公開情報だけ。ツモ和了を優先。聴牌できる手は暗カン後の待ちの種類が減らないときだけ、聴牌でない手は4枚目が他の手牌と数式面子の部分を作らない（遊んでいる）ときだけ暗カン。AI の係数・個性は変更していない。旧ルールでは選択肢がないので常に判断なし（従来と同一）。
- AI の未知牌の計算（`unseenCounts`）は公開されたドラ表示牌を見えている牌として数える。
