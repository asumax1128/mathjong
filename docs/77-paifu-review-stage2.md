# 数雀｜牌譜の振り返り 第2段階（実装記録）

正式仕様：[docs/76](https://github.com/asumax1128/mathjong/pull/70)（PR #70 `docs/76-paifu-review-stage2-spec.md`）。第1段階（PR #69・docs/74）で保存した通常対局の牌譜を、**自分の視点で1判断ずつ**振り返る画面を追加した。戦績の集計は第3段階（別PR）。

変えていないもの：AI 12人・鳴きの確率、ルール・得点・精算、聴牌サポート Ver.1、2回タップ・長押し、再現 URL、localStorage のキー、牌譜の保存形式（schemaVersion 2・DB・索引の形）、`src/engine/` のすべてのファイル（CI で main と比較）。mainマージ・Pages公開はしていない。

## 画面と操作
| 画面 | 内容 |

| 一覧 | 1行＝1試合：日時（開始日時。要約の前は保存日時）・数学Ⅰ／Ⅱ・1/4/8局戦・**完走／中断／記録途中**・局の数（中断の理由）・相手3人・**自分の順位と最終点（完走だけ）**。0件・一覧を読めない・読めない記録N件（壊れた行・別の版）を文で案内。10件ずつ（「さらに表示」） |

## 牌譜の再生と情報の公開
- **読込**：`store.loadPrivate(id)`（保存時と同じ：索引と本文の対応・SHA-256・`decodePaifu` 相当の完全な検証）。検証は Web Worker（`src/ui/paifu-worker.js`。使えなければ主スレッドで分割）で行い、検証済みの正規化 JSON を主スレッドで読み直して凍結する（`src/ui/paifu-system.js` の `decode`。`src/ui/paifu-storage.js` は `decode` を差し替えられるようにしただけで、保存形式・既定の動作は同じ）。破損は `corrupt`、版の違いは `unsupported-version`、削除済みは `not-found` として理由を表示し、再生しない。
- **射影**（`src/ui/paifu-review.js`・DOM なし）：検証済みの記録を閉包の中だけに持ち、局ごとに独立した `Game`（記録と同じ設定）へ記録された行動を順に適用し、各行動の後の **digest を記録と照合**しながら、時点ごとの値（frame）を作る。frame に入れるのは `Game.viewFor(自分)` と同じ境界の情報だけ：自分の手牌、全員の河（牌の種類・ツモ切り・リーチ宣言牌）、公開面子、各席の手牌の枚数、親、リーチ宣言、ドラ表示牌、残り枚数、通常ツモの回数、持ち点・供託（局の途中はリーチ宣言料を引いた値）、自分のフリテン・リーチの待ち。**牌の id・山・王牌の未公開の牌・他家の手牌の中身・他家の待ちとフリテンは入れない**。
- **他家の判断を時点にしない**：他家の見送り、後続のロンの判断を待つ未確定のポン・チーは、実際の対局でも見えない（他家が鳴けたことが分かってしまう）ので、独立した時点にしない。時点は**安定した点**（誰かの手番・自分の判断・局の終わり）だけで、前の時点から公開の出来事（`Game.events`）が増えたか自分の行動があったもの。他家の鳴き・ロンの判断待ちの間に起きた出来事は次の安定した点へまとめる（打牌の時点は、自分の判断待ちでなければ次のツモ・鳴きまで進んだ状態）。これで、他家が鳴けたかどうかで時点の数・区切り・「次の判断者」の表示が変わらない。局の一覧にも行動の数は出さない。記録が他家の判断待ちの途中で終わった（中断）ときは、その後ろの出来事を時点にしない。
- **後の情報を前に出さない**：frame はその時点までの行動を適用した `Game` だけから作る。局の結果は局の最後の時点だけ。和了の形を示すため和了者の手牌だけを局の最後に出す（他の席の手牌は出さない）。
- **中断・記録途中**：実在する検証済みの局・判断までだけ。未精算の局は結果を作らず「中断（記録途中）のため、ここまで」と示す。局が1つもない記録は「再生できる局がありません」。
- **画面の値**：画面へ渡すのは frame と公開してよい要約（相手の名前・順位・最終点・状態）だけ。記録の本文を DOM・URL・console・localStorage・sessionStorage・アプリの状態（`S`）へ出さない（E2E で確認）。再生はゲーム本体（`S.game`・`S.match`）・保存・削除・削除の世代に触れない。
- **一覧の要約**：索引には相手・順位がない（保存形式を変えない）ため、表示中の行だけを1件ずつ読み込み・検証して要約にし、記録は手放す（全件の一括読込はしない。10件ずつ）。読む間に更新・削除された行は次の一覧で読み直す。
- **非同期と取り消し**：局の frame は 8ms ごとにイベントループへ戻りながら作る。画面の世代（`gen`）で、読込中に戻った・別の局を選んだ・二度押した場合の古い結果を捨てる（後から古い画面を描かない）。直近3局の frame だけを保持。

## 未解決・判断が必要な点
- 局の選択は全局の名前（東1局・連荘の印・未精算）を最初から並べる。終わった試合の振り返りなので、局の進み（連荘したこと）は最初から分かる。
- 一覧の要約は表示中の行を1件ずつ検証するため、8局戦が多いと相手・順位の表示まで少し時間がかかる（10件ずつ・Worker）。索引に公開用の要約を持たせる案は保存形式の変更になるため、この段階では採らない。
- 和了の局の最後だけ和了者の手牌を出す（実際の対局の結果画面と同じ）。他家の手牌は出さない（実際の対局の「全員の手牌を見る」は振り返りでは出さない）。
- 個別削除は作っていない（既存の全件削除だけ）。
- 既知の課題（docs/76）：E2E の複数タブ待機の不安定さ、ブラウザ外から DB を全消去した場合の削除の世代の ABA。iPhone Safari 実機は未確認（オーナーの受入）。
