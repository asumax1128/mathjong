# 数雀｜新ルール実装計画：ドラ・王牌・暗カン・数学Ⅱ通常ツモ24回
決定日：2026-10-30 JST。ユーザーがシミュレーション終了と「採用する方向で次に進む」を承認。
状態：**実装前仕様ゲート／公開未承認**。この文書自体は新ルールを実装しない。

## 固定の製品要件
- 数学Ⅰはツモ上限を増設しない。数学Ⅱはプレイヤーごと**通常ツモ24回まで**（親の最初のツモ含む）。25回目が必要なら流局。鳴いた直後の打牌は通常ツモ回数に数えず、河26枚程度は許容し、河の枚数自体には硬い上限を設けない。
- 王牌14枚を別領域で管理。初期ドラ表示は1枚、表示牌の次の牌種がドラ。ドラの表示候補が関数牌なら**最大1回だけ別候補を採用**、2回目も関数牌ならそのまま確定。関数牌ドラを禁止しない。
- 暗カン（同種類の物理牌4枚）を初期対象。大明カン・加カンは対象外。カン成立時、通常山の残りから1枚を王牌へ移し嶺上牌1枚を自分の手牌へ移す。カンドラを増やす。暗カンは門前維持。リーチ中暗カンは初期版では禁止する設計案（詳細テスト必須）。
- 暗カンを3枚面子と同等の**1面子**として数え、4枚目の物理牌も槓子として保持。和了条件は既存3面子9枚形を崩さない。嶺上ツモの優先・終局条件・上限4回、他家への表示/牌譜記録を決定・テストする。
- ドラは和了役を単独で作らず、通常和了の加点候補として計上。1枚+1点は暫定。役満との優先、既存リーチ/三暗刻/鳴き役判定との互換性を明文化してから実装する。

## 安全な開発順序
1. 別モジュールで`DeadWall`（14枚固定、表示候補、嶺上4枚、カン時補充）とドラ候補確定を実装。seedの再現・物理牌の一意性、候補を採用しなかった物理牌の保持をユニットで網羅。
2. Gameに「新ルール有効」フラグを設け旧ルールを完全保護。通常ツモ上限をモード別に実装。鳴き/流局/親初回ツモ/山切れ/カン補充と一致させる。公開情報にのみドラ表示情報を載せ、他家手牌・山/裏牌は漏らさない。
3. Gameへ暗カン合法手・宣言・槓子・門前保持・嶺上/ドラ追加、既存9枚和了、AIの合法手・自動パス・リーチに回帰テスト。嶺上前後の手牌枚数保存を確認。
4. 数学Ⅰ/Ⅱで同一seedの回帰、旧seed結果一致、牌ID総数一定、和了/流局/ドラ・嶺上/暗カン、AI公平性と得点の詳細CI。長局を重点検証。通常モードの旧seed結果・旧testの合格を必須。
5. Ver.0.7を土台としてドラ/暗カン/残りツモ/カンドラのUIを追加。iPhone Safari縦・横、320px等のレイアウト・操作テスト。
6. Ver.0.8 PR #37の既存ブランチは変更しない。新ルールの全イベントを将来の牌譜schemaへ対応できる形で仕様化し、統合時に版互換を検査する。
7. テスト/独立監査を経てオーナーに実機テスト版として提示。**明示的な公開承認があるまでmainへマージ・Pages公開しない**。
