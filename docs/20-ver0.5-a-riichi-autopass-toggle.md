# 数雀（MATHJONG）Ver.0.5-A（仮）実装記録 — リーチ＋対戦画面のチー・ポン自動パス切替

作成: 2026-10-26 ／ 基準: main `cd37c62`（Ver.0.4-B）／ ブランチ `feature/riichi-autopass-toggle`
版（暫定）：画面 `0.5.0-a`・エンジン `0.5.0-a`。リーチで規則が変わるため、エンジンの版も上げた。
「Ver.0.5-A」は実装側の仮の名前。正式な版名はオーナーが決める（ROADMAP の Ver.0.4-C 効果音案とは別の作業）。

## 1. 確定仕様（オーナー承認済み）
- 門前で聴牌しているときに宣言できる。自分の手番で「リーチ」を選び、宣言する捨て牌を選ぶ。
- 聴牌の判定：9枚から1枚捨てた後の8枚について、和了待ちがあるか。
  - 既存の和了判定（`analyzeWin`：数式面子・刻子・特殊和了）をそのまま使う。
  - 宣言できる捨て牌が複数あるときは、プレイヤーが選べる。
- リーチ後：
  - ツモ切りだけ。チー・ポンはできない。ロン・ツモはできる。
  - これらは UI だけでなく、エンジンが拒否する。
- 和了時は基本点に＋1点。親子の精算の倍率は従来どおり（子ロン 4B・親ロン 6B・子ツモ 4B・親ツモ 6B。B にリーチの＋1を含む）。
- 数学Ⅰ・数学Ⅱの両モードに対応（`config.rules.riichi`）。旧規則（Ver.0.2.1 互換）では無効。
- プレイヤーと AI 3人の両方。AI のリーチは対戦画面に表示する。
- 仮決定3項目（2026-10-26 承認）：
  1. **役満では＋1を加算しない**（既存の役満優先：通常の点・役を加算しない）。
  2. **公開済みの牌で実際の残り待ちが0枚でも、数学的に聴牌ならリーチを認める**。
     - ただし、自分の手牌だけでその種類を全部使い切っている牌は、待ちに数えない。
     - 総枚数は `rules.types[t].copies` を使う（関数牌は数学Ⅰで12枚、数学Ⅱで16枚。4枚とは限らない）。
  3. **山の残り枚数による制限はない**。流局・ツモ・ロンの進行は従来どおり。
- 対象外：リーチ棒・供託、一発、ダブルリーチ、裏ドラ、フリテン。既存の仕様も変更していない。

## 2. エンジン（`src/engine/game.js`）
- `riichi[seat]`：`null` または `{ tile: 宣言牌の id, turn }`。
- `waitsOf(counts, exposed)`：待ちの種類。`counts[t] < copies` の種類について、`analyzeWin` で判定する。入力は変更しない。
- `riichiOptions(seat)`：`[{ type, ids, waits }]`。
  - 条件：規則が有効・自分の打牌番・門前・未リーチ。
  - 同じ局面（`events.length`）では結果を再利用する。
- `discard(seat, tile, { riichi })`：
  - リーチを宣言するとき：宣言できる種類でなければ `riichi not possible`。
  - リーチ中：ツモ牌以外なら `riichi: tsumogiri only`。再宣言なら `already in riichi`。
  - 宣言牌は河に `riichi: true` を付け、記録に `{ type: 'riichi' }` を残す。
- `chiOptions`・`ponOption`：リーチ中は空。宣言待ち（`_openClaims`）にも出ない。ロンの判定は従来どおり。
- `_withRiichi`：和了の analysis に「リーチ +1」を加える（役満では加えず、`riichi: true, riichiBonus: 0` だけ）。`result.points` は加点込み。
- `viewFor` にリーチ状態（公開情報）を追加した。
- `pending()` の形は変えていない。

## 3. AI（`src/engine/ai.js`・`ai-levels.js`）
- リーチ中はどの難易度も、ツモ和了できればツモ、できなければツモ切り。
- 打牌の選び方は各難易度のまま。決めた打牌で聴牌になる場合に、リーチするかを判断する（`riichiDecision`）。
  - 初級：聴牌ならいつもリーチ。
  - 中級・上級：待ちの牌が自分から見えていない分で1枚以上残っているときだけリーチ。
  - 判断材料は、自分の手牌と公開情報（`unseenCounts`）だけ。
- 上級の危険度モデルに、他家のリーチ（公開情報）を特徴量として加え、リーチのある対局で当てはめ直した。
  - 再計算：`node tools/calibrate-advanced.mjs --mode math1|math2`。
  - AUC（学習データ上）は 0.916 で、リーチなしの版の 0.75〜0.77 から上がった（リーチした他家は聴牌が確定しているため）。
  - AUC の同点処理は Ver.0.4-B の P3-2 のまま（未修正）。
- 中級の互換：リーチの規則を無効にした数学Ⅰ・Ⅱで、対局ログの要約が Ver.0.4-A／B と完全に一致する（`tests/ai-levels.test.js`）。
  - リーチありの対局ログは、新しい記録値（`GOLDEN_RIICHI`）で固定した。

## 4. 画面（`src/ui/app.js`・`styles.css`）
- 打牌番で聴牌になる牌があれば「リーチ」ボタンを表示する。
- 押すと宣言牌の選択に入る：
  - 聴牌になる牌だけが選べる（赤枠）。ほかの牌は薄く表示し、タップできない。
  - 「リーチして捨てる」「やめる」のボタンを出す。ツモ和了できるときはツモも出す。
- リーチ中：
  - 状態欄に「リーチ中：ツモ切り」と表示し、ツモ牌だけが選べる。
  - 「ツモ切り」ボタンを出す。和了できるときは「ツモ」も出す。
- 自分・AI のリーチ状態：パネルに赤い「リーチ」表示、河の宣言牌は横向きで赤枠。打牌のメッセージは「○○ がリーチ：… を捨てました」。
- 結果画面：
  - 役の一覧に「リーチ +1」、合計点・精算は加点込み。
  - 役満のときは「リーチ（役満のため加点なし）+0」と表示する。
- 画面内のルール説明にリーチを追加した。

## 5. チー・ポン自動パスの切替を対戦画面へ移動
- 手牌の下の操作の列に「チー自動 ON/OFF」「ポン自動 ON/OFF」を置いた（自動整列・ヒントの前）。
  - ON は緑地に白文字、OFF は枠だけ。文字でも ON/OFF を示し、`aria-pressed` も付ける。
  - 高さ 44px 以上。320px でも1行に収まる。
- 2つは独立して切り替えられ、自分の手番以外でも切り替えられる。
- 保存キーと値は従来どおり（`mj-chi-autopass`・`mj-pon-autopass`、`'1'` だけ ON）。
- 切り替えると、設定を保存してボタンだけを描き直す。
  - 全体を描き直さないので、ドラッグ中の並び替えや、表示中の宣言を妨げない。
  - 次に発生する宣言から反映する。表示中の宣言の選択肢は、宣言ごとの方針（`claimPolicy`）で固定されたまま。
- ロン・ツモは自動で見送らない安全仕様は不変（`src/ui/autopass.js` は変更なし）。
- 設定画面のスイッチは削除し（二重管理しない）、切替の場所と安全仕様の説明だけを残した。

## 7. 強さの確認（seed 2、集計結果 `docs/data/v05a-riichi/`）
| 条件 | 組／試合 | 平均順位の差 | 平均得点の差 |
|---|---|---|---|
| 数学Ⅰ・4局戦 上級1 vs 中級3 | 150／600 | −0.22±0.044 | +4.4±1.0 |
| 数学Ⅰ・4局戦 初級1 vs 中級3 | 100／400 | +0.59±0.071 | −17.3±1.9 |

- 確認したのは4局戦だけで、8局戦は未確認。
- 1人1試合あたりのリーチは 2.1〜2.8 回。
- AI どうしの対局では、和了の大半がリーチ後（数学Ⅰ 200局で 177/200、数学Ⅱ 194/200）。
  - 9枚の手は聴牌が早く、＋1点が大きく効く。役点のバランスへの影響はオーナーの判断事項。
- 1判断の平均時間：数学Ⅰの上級で約7ms、数学Ⅱで約21ms（Node.js 4並列）。
  - リーチの判定（聴牌の確認）による増加は小さい。
  - iPhone では未測定。
