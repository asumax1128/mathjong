## 2. ① 牌の表示（負の無理数など）
- 原因：負号（−）と根号（√）をフォントの字形で描いていたため、端末のフォント（iPhone のヒラギノなど）で幅が変わり、`−√3` などが牌の枠を超えることがあった。値の幅を牌の幅に合わせる仕組みもなかった。根号を含む分数は、分子・分母の行の余白で実際より高くなっていた。
- 修正（`src/ui/render.js`・`styles.css`。牌の寸法は変えない）：
  - 負号・根号を CSS で描く（固定の幅・太さ。文字の − と √ は読み上げ・検索用に要素へ残し、大きさを持たせない）。
  - 値・角度ごとに必要な幅・高さ（em）を見積もり（`--vw`・`--vh`・`--aw`・`--ah`）、牌の内側に入らないときだけ文字を小さくする（コンテナクエリ `cqw`・`cqh`）。収まるときは従来の大きさのまま（一律の縮小はしない）。
  - 分数の分子・分母を flex にして、根号の行の余白で高くならないようにした。
- 確認：数学Ⅰ・Ⅱの全種類×手牌・自分の面子・m・s・xs・河・他家の面子・ドラ表示（`--rw` 13〜28px）×5画面で、枠からのはみ出し・分子分母の重なり・負号の欠けがないこと（修正前は97件、修正後0件）。

## 3. ② フリテン（版2）
- **捨て牌のフリテン**：自分の待ち（和了の形になる牌の種類。役の有無は問わない）のどれかを、その局に自分で捨てていればロンできない。鳴かれて河から移った牌も「捨てた牌」に含める（一般的な麻雀と同じ。`discarded` に種類で記録）。
- **同巡のフリテン**：ロンできる牌を見送った（ポン・チーを選んだ場合も）、またはフリテンでロンできなかったとき、自分の次の通常ツモまでロンできない。鳴き・鳴いた後の打牌・他家の行動・嶺上ツモでは解除しない。
- **リーチ後の見逃し**：リーチ後に見送ると、その局の終わりまでロンできない。
- どれもツモ和了はできる。判定はエンジン（`_openClaims` でロンの選択肢を出さない＝`respond('ron')` も拒否）。AI はエンジンが出した選択肢から選ぶので、フリテン中にロンを選ばない。他家の AI にはフリテンの状態を渡さない（記録 `events` にも残さない）。
- 画面：フリテンのとき手牌の上に「フリテン」と短い理由（捨て牌に待ち／見逃し（次のツモまで）／リーチ後の見逃し）、和了の牌が出たのにロンできなかったときはその牌も表示。詳しい説明は title・読み上げに入れる。ガイドのルールにも説明。

## 4. ③ リーチの待ち
- リーチの確定時に待ちを記録（`riichiWaits`、その席だけ。他家の AI に渡る `riichi[]` には入れない）。暗カンを含む門前判定と同じ `riichiOptions` の待ち。
- 手牌の上に「待ち」と実際の牌、各待ちの**自分から見えていない残り枚数**（全員の河・公開面子・ドラ表示牌・自分の手牌を除いた枚数。他家の手牌・山の中身は使わない）。フリテンなら同じ行に「フリテン ロン不可」。

## 5. ④ 関数牌のポン禁止（版2）
- `ponOption` が関数牌（sin・cos・tan）では候補を作らない → ポンのボタンなし・AI も選べない・`respond('pon')` はエンジンが拒否。角度牌・結果牌のポン、関数牌の暗カン・刻子での和了（三暗刻・対々和・関数一色）は従来どおり。鳴きの回数の上限は変更なし。
