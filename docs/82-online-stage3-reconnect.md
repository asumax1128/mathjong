# 数雀｜オンライン対戦 段階3「切断と復帰・再戦・長い試合」実装メモ

- 設計の正本は [docs/79](79-online-play-design.md)（特に「8. 切断・復帰」）。段階1・2の実装メモは [docs/80](80-online-stage1-lobby.md)・[docs/81](81-online-stage2-match.md)。
- 未決事項 U1〜U11 は、設計書の推奨どおりに決定済みとして実装した。
- **エンジン（`src/engine`）は変更していない。**

段階1・2の制約は、この段階でもそのまま守っている。

- 接続先はエミュレータだけ。
- 入口は「ローカル開発環境＋`?online=emu`」のときだけ出す。
- `ONLINE_PUBLIC = false`。

## 1. 実装した内容

### 1.1 ゲストの切断と代打ち（docs/79「8.1」「8.2」）

- **離席になる場面は3つある。**
  - **切断**：ホストが `presence` を見ていて、ゲストの `online:false` が**10秒**続いたら離席にする。
  - **時間切れ**：手番・宣言の時間切れが**3回続いた**ら離席にする（段階2で数えている `timeouts` を使う）。
  - **自分から部屋を出た**：対局中にゲストが「部屋を出る」を押すと、`act` に `away` を送ってから抜ける。
- **代打ちの動き**
  - 離席中の席は、**中級の既定キャラクター（おうすけ）**が代打ちする。
  - 代打ち用の乱数は CPU の乱数と分けている。そのため、代打ちが入っても CPU の判断は変わらない。
  - 手番の途中で離席になったら、代打ちがすぐに打つ。
  - 宣言・再質問の窓は、離席した席を待たずに締める（締めるときに代打ちが判断する）。
  - 次局の「次へ」の待ちからも外す。
- **全員の画面への表示**
  - 離席中の人の名前に「（代打ち）」を付ける。
  - `seats/$seat/away` にも書く（全員が読める）。
  - 本人の画面には、帯に「代打ち中：対局に戻る」のボタンを出す。

### 1.2 ゲストの復帰

- 同じ端末（同じ匿名 uid）で「オンライン対戦」を開くと、入っていた部屋の自分の席へ**自動で戻る**。
  - 端末に保存した部屋コード `mj-online-room` を使う。
- 戻ったときの状態：
  - ホストが `presence` の再接続を見て、離席を解く。代打ちが止まり、`timeouts` は0に戻る。
  - 画面は、その時点の `pub`・`priv` から組み上げる（局の途中からでも正しく描く）。
- 時間切れで離席になった人（接続は切れていない）は、「対局に戻る」ボタン（`act` の `back`）で戻る。

### 1.3 ホストの切断と再開（docs/79「8.3」）

- **一時停止**
  - ホストは、開始時に `onDisconnect` で `meta.status=paused`・`meta.pausedAt=サーバー時刻` を予約する。
  - ホストが切れると、ゲストの画面に「**ホストの復帰を待っています（残り N 秒）**」を出す。残りは `pausedAt＋90秒` から数える。
- **行動の記録**
  - 適用した行動を、1つずつ `host/log/eNNNNNN` に保存する。
    - 中身は `{ r: 局, s: 席, a: 行動, src: human|cpu|proxy|timeout|overridden }`。
    - 保存は、配信と同じまとめ書きの中で行う。
  - `host` はホストだけが読める。
- **再開（再生）**
  - ホストが同じ端末で開き直すと、記録を局の初めから再生し、同じ局面に戻る。
    - 人間・代打ち・時間切れの手は、記録をそのまま適用する。
    - CPU の手は、`decideCharacter` をもう一度呼んで同じ乱数を消費し、記録と一致することを確かめる（不一致は数える）。
    - 試合の状態（持ち点・親・連荘・供託）と AI の公開履歴も、局の精算をたどって作り直す。
  - 配信の番号（sid・seq）は、前の配信の続きから数える。切断の前に届いた古い `act` を、新しい窓への応答と取り違えないためである。
  - `act` の購読の最初の値は既読にする。
  - 再開すると `status=playing` に戻す。
  - 遅れて届いた古い接続の切断で `paused` になっても、動いているホストが `playing` に戻す（見張り）。
- **90秒を過ぎた場合（U3）**
  - ゲストの画面は「**途中終了**」になる（結果は確定しない。参考に、精算が済んだ局までの持ち点を出す）。
  - 猶予を過ぎてからホストが開き直しても、試合は続けず、部屋を閉じる。
  - ホストの引き継ぎはしない。

### 1.4 再戦

- 最終結果に「**もう一戦**」と「部屋を出る」を出す。
- ゲストの「もう一戦」：`act` の `ready` を送る。ホストが受付の窓 `rematch` で集め、何人押したかをホストのボタンに表示する。
- ホストの「もう一戦」：部屋をロビーへ戻す（`reopenLobby`）。
  - 押した人とホストだけを残し、席を詰め直す（ホストが席0）。
  - `matchNo` を1つ進める。
  - 前の試合の `pub`・`priv`・`host` を消す。
  - CPU の選択（`meta.cpus`）は残す。
- ロビーに戻った後：
  - 押した人はロビーへ移る。ロビーには、コードを知っている人が新しく入ることもできる。
  - 押さなかった人には「再戦は『もう一戦』を押した人だけで始まりました」と出し、部屋から抜ける。
  - 2試合目は、段階2と同じ「開始」で始まる（席と最初の親を決め直す）。

### 1.5 ルール断片の追加（`firebase/mathjong-rules.cjs`）

- `meta.status` に `paused` を追加した。
- `meta.pausedAt`（数）を追加した。サーバー時刻の置き換え値を含む。
- `seats/$seat/away`（真偽値・人間の席だけ）を追加した。
- ルール試験は **138件**（段階3で25件追加）。
  - ホストだけが一時停止・再開できる。
  - `away` は人間の席だけで、真偽値だけ。
  - 行動の記録はホストだけが読み書きできる。
  - 再戦（ロビーへ戻す）はホストだけができる。
  - 再戦のロビーには新しい人も入れる。

## 2. 設計書からの変更点

1. **復帰は、同じ端末で「オンライン対戦」を開くと自動で行う。**
   - 再読み込みの後はタイトルから始まるので、入口のボタンを1回押す必要がある。
   - 設計書ではゲストの復帰を「部屋に入り直す」と書いていたが、コードの入力を省いた。
2. **代打ちの開始。** 手番の途中で離席になったら、その場で代打ちが打つ（設計書は「その席の判断の番から」）。宣言の窓は、締めるときに代打ちが判断する（設計書どおり）。
3. **ホストの待ちの判定**
   - ゲストの画面が、`meta.pausedAt`（サーバー時刻）＋90秒で判定する。
   - ホストがいないため、途中終了を DB に書く人はいない。ゲストは各自の画面で終了とし、ホストが戻ったときに部屋を消す。
4. **途中終了の画面**
   - 「最後に精算済みの局までの持ち点・順位を表示」（設計書）は、ブリーフの「結果は確定しない」に合わせた。
   - そのため「参考」として持ち点だけを出す。
5. **行動の記録の形式**
   - `host/log` に1行ずつ JSON 文字列で保存する。局をまたいで1本の列とし、局の区切りは `r` で分かる。
   - 設計書の「局ごとの行動の列＋AI の判断の記録」は、AI の手も同じ列に `src:'cpu'` で入れる形にまとめた。
   - `stateDigest` の照合は、CPU の手の一致の確認で代えた（不一致の件数を `replayMismatch` に数える）。

`tests/online-reconnect.test.js` の項目：

- **再生**
  - 途中の5か所で作り直しても、局の記録・手牌・試合の状態・履歴が一致する（代打ちの手を含む・CPU の手の不一致0）。
  - 記録の半分から再開して最後まで打つと、同じ最終結果になる。
- **離席**
  - 手番中の離席で、代打ちがすぐ打つ。
  - 宣言の窓は離席した席を待たない。
  - `away`・`back` が働く。
  - 時間切れ3回で離席になる。
- **再戦の受付**
- **ホストの待ちの判定**
- **偽バスでの流れ**
  - ゲストの切断：10秒で代打ちになり、同じ uid で戻ると自分の席から打てる。
  - ホストの切断：`paused` になり、再生で同じ局面から再開して完走する。その後、再戦でロビーへ戻り、2試合目を開始する。
  - 押さなかった人は外れる。

`tests/e2e/online-reconnect.mjs` の項目：

- **ゲストの切断（タブを閉じる）**
  - 約10秒で代打ちになる（ホストの画面に「代打ち」・`seats` に `away`）。
  - 試合は止まらない。
  - 同じ端末で開き直すと、自分の席に戻って打てる。
- **ホストの再読み込み**
  - ゲストに「ホストの復帰を待っています（残り90秒）」と出る（`meta` は `paused`）。
  - ホストが開き直すと、同じ局面・同じ持ち点から再開する。
  - そのまま4局戦を完走し、両端末で結果が一致する。
- **ホストが戻らない場合**（`?onlineHostGraceMs=3000`）
  - ゲストに「途中終了（結果は確定しません）」と出る。
  - 遅れて戻ったホストは、部屋を閉じる。

試験用のフック（ローカルだけ・既存の流儀）：

- `?onlineCpuDelay=`：CPU・代打ちの手番の間
- `?onlineHostGraceMs=`：ホストの猶予
- `?onlineAwayMs=`：切断から代打ちまで

CI：`.github/workflows/online-lobby.yml` に、ジョブ `emulator-stage3`（reconnect・long）を追加した。時間がかかるため、既存のジョブと並行して動かす。
