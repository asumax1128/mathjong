# 数雀｜役の追加：正負対称・補角対・等差三連（エンジン 0.8.0・点数確定）

## 1. 仕様

| 役（id） | 点 | 成立の条件 | 不成立の例 |
|---|---|---|---|
| **正負対称**（seifu） | 2 | 異なる2面子の値が +v と −v（v≠0）。厳密値 (p/q)√r の和が0かつ0でないことで判定（文字列の符号は見ない） | 0 と 0、同符号、絶対値が違う |
| **補角対**（hokaku） | 2 | 異なる2面子の角度の和が180°。関数・値は問わない | 90°と90°、和が180°でない |
| **等差三連**（tousa） | 3 | 3面子の角度を小さい順に並べた差が等しく、公差が正 | 公差0、等差でない、330・0・30（360°の回り込みは数えない）、**象限三角が成立する手**（下記） |

- 数式面子3つの和了だけ（刻子が混じると不成立）。門前限定ではない。既存の役と重なれば加算。
- 有効：ruleset 1・2 の対局。従来ルール（ruleset 0）・legacy では数えない。
- 点数はオーナー決定で確定：正負対称2・補角対2・等差三連3（`src/engine/config.js` の `ROUND2_YAKU`。値は暫定時から変更なし、`provisional` を外した）。
- **象限三角が成立するときは等差三連は付かない**（オーナー決定）。象限三角の3角度（30・45・60／120・135・150／210・225・240／300・315・330）は必ず公差15°の等差なので、同じ角度の並びを二重に数えない。
  - 実装：`rules.js` の等差三連の判定の中で、象限三角が成立する（かつ象限三角が有効な設定）なら不成立にする。和了・待ち・役ヒントはすべて `evaluateMelds` を通るので同じ結果になる。

## 2. 実装

- `rules.js`：3つの検出器（既存の `douchi` などと同じ流儀）。`evaluateMelds`・`analyzeWin` に `round2` を追加し、`round2: true` の役は `round2` を渡したときだけ評価する。
  - **AI の方針は変えない**：AI（`ai.js`・`ai-levels.js`・`character-ai.js`）は `evaluateMelds` を直接呼び、既定（round2 なし）のままなので期待値に新しい役は入らない。
- `exact.js`：`sumIsZero(x, y)`（厳密値の和が0か）。
- `game.js`：`round2Yaku`（既定 true）→ `round2YakuRule = ruleset>=1 && round2Yaku!==false`。ツモ・ロンの判定と待ち（`waitsOf`）に渡す。
- **画面の補助にも渡す（追加の変更）**：
  - 役ヒント（`yakuhint.js` の `yakuCandidates`・`warmUp`）：`round2` を受け取り、評価のキャッシュの鍵にも含める。`app.js` から `g.round2YakuRule` を渡す。渡さないと新しい役は候補に出なかった。
  - 待ちの表示（`waits-view.js`・`discard-preview.js`・初心者の部屋の実戦形式）：「役があって和了できるか」に `round2` を渡す。
  - オンラインのゲスト側の表（`online-protocol.js` の `buildRemoteTable`）に `round2YakuRule: true`・`tsumoIppatsuRule: true`（ホストの Game と同じ）。
- 役ガイド（`guide.js`）に3役の条件と数式例。docs/03 の役一覧を更新。

## 3. 版と牌譜

- エンジン 0.8.0、画面 0.7.3（和了の点が変わるため。オンラインの部屋は `appVersion` が同じ端末だけで組む）。
- `PAIFU_ENGINE_FEATURES`：`0.6.0`＝{一発・門前ツモなし、新役なし}、`0.7.0`＝{一発・門前ツモあり、新役なし}、`0.8.0`＝{両方あり}。牌譜の再生は記録の `engineVersion` の数え方で行う。0.7.0 以前の牌譜は追加前の点数で再生でき、読み取り専用（記録の追記は現在の版だけ）。知らない版は拒否。

## 4. 頻度測定（`tools/yaku-frequency.mjs`）

方法：
- ruleset 2・キャラクター AI 4人（12人から席ごとに選ぶ）・1局を数学Ⅰ・Ⅱで各 3000 局（seed 1）。
- 同じ局（同じ席の並び・同じ乱数の種）を **新しい役なし（`round2Yaku: false`＝main と同じ採点）** と **あり** で1回ずつ打って比べる。
- `tools/simulate.mjs` は ruleset 0 専用なので、新しい測定用の道具を追加した。`--points seifu=3,...` で点を config の値だけ差し替えて測れる。
- 結果の JSON：`docs/validation/yaku-round2-frequency.json`（数学Ⅰ 519 秒・数学Ⅱ 2156 秒）。

読み取り：
- AI は新しい役を狙わないので、打ち方はほぼ同じ（99.3〜99.5% の局が同一）。差はほぼ採点だけから出る。
- 和了率は変わらない（門前は役なしで和了でき、鳴いた手で新しい役だけが役になる形もまれ）。
- 数学Ⅰの多い組み合わせ：補角対単独 185、補角対＋三関制覇 177、正負対称単独 73。
- 除外前は「象限一色＋象限三角＋等差三連」が数学Ⅰで 85 回あった（象限三角は常に公差15°の等差）。オーナー決定により、象限三角が成立する手には等差三連を付けないようにした。その分だけ等差三連と平均点が下がり、ほかの役の頻度は変わらない。
- 数学Ⅱでは負の値が増えるため、正負対称が多い（数学Ⅱの最多は正負対称単独 127）。
